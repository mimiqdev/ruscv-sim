## Limits and owner decisions

This is one RV64IMA/Zicsr M/S/U hart with abstract Access Register and physical Access Memory, `datacount=4`, `progbufsize=0`, no implicit EBREAK, no SBA, no triggers, and no execution of instructions in Debug Mode. FENCE.I and DRET remain illegal. There is no Linux/SBI, second hart, full ISA/Debug certification, or new ACT4 claim. Existing performance comparison/publication/calibration remain deferred and the A10 oracle remains unsealed.

U5 proves the documented OpenOCD/GDB operations and fixed Spike comparison. The selected profile differs from Spike in the documented reset PC and `dcsr` fields. The expected fence warning follows the absence of a program buffer. GDB's final continue does not return; the script observes target exit/disconnect and then stops GDB/OpenOCD. A successful flat RAM test does not establish native PLIC side effects.

The [program-buffer successor proposal](../../proposals/post-stage6-program-buffer-debug.md) is Draft and informational. D1–D9 recommend two buffer words with implicit EBREAK, a non-addressable DM instruction source, guest/debug Zifencei, bounded debug instruction restrictions, four data-autoexec bits, and a mutable component DMI-read API. OpenOCD bulk-transfer acceptance requires those autoexec bits. OpenOCD virtual-memory access is not claimed with two words; a direct Hart/DMI fixture must prove MPRV/Sv39. SBA remains a later goal. All choices and the required accepted ADR amendments await the owner.

The remaining boundary is approval and delivery, not a missing local gate. The owner must decide code/document merges, formal Stage 6 completion, the successor direction and D1–D9, and accepted ADR amendments. This change archives no contract, edits no accepted ADR, and activates no successor.
