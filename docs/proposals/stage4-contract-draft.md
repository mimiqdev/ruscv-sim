## 1. Proposed objective and architecture

The objective, if later approved, is to connect one privilege and address-translation profile to the common physical port so a public ELF guest can run with translation on. The selected profile is RV64IMA plus Zicsr, with M, S, and U and with M as the boot and handler mode (D1). Zifencei is not claimed. The selected modes are Bare and Sv39 (D2). Fetch, load, store, and AMO effective addresses are translated. A permission, reserved-bit, or misaligned-superpage violation becomes an architectural page fault that keeps the original virtual access kind and address. A physical failure during a walk read or an A/D write-back becomes an access fault of that same kind (D3, D4). Hardware sets A and D. PMP is not enforced, and the standard PMP CSRs read as zero (D5). No A8, A9, or A10 guarantee is weakened.

Boundary, from roadmap Stage 4, as narrowed by §8. Page-table reads and A/D write-back flow through the same physical result taxonomy. The original virtual access kind and address are retained when mapping physical faults and page faults. A successful A/D write stays visible and is not a commit effect of a faulting instruction (ADR-0001 §2). There is no translation cache on the public path in v1, so the roadmap's "TLB integration" deliverable is deferred (M4). PMP enforcement is explicitly excluded (D5). The public ELF guests cover bare, mapped, permission-fault, page-walk-fault, A/D, and SFENCE.VMA cases. Image placement stays on the current image-base path, and translation sits in front of it (D7).

This is the proposed **first bounded milestone** of virtual-memory work. One hart, no OS or Linux boot, no hypervisor, no multi-hart TLB coherence, and no interrupt virtualization. Sv48, Sv57, PMP enforcement, and a translation cache stay out. A later milestone may add them.

## 2. Entry evidence and existing controls (verified at the baseline)

These are available seams, not capability claims. Component presence is not public-path support. Every path below was read at `d5258f5`.

- **Privilege state exists and is Hart-owned, and the public path barely exercises it.** `PrivilegeMode { User, Supervisor, Machine }` and staged trap transitions live in [`src/core/mod.rs`](../../src/core/mod.rs). `mret`, `sret`, and `uret` plus `ecall` and `ebreak` live in [`src/isa/rv64i/system.rs`](../../src/isa/rv64i/system.rs). CSRs, including `satp` at `0x180`, live in [`src/csr/mod.rs`](../../src/csr/mod.rs). [`tests/privilege_transition_test.rs`](../../tests/privilege_transition_test.rs) has 19 tests, [`tests/csr_access_test.rs`](../../tests/csr_access_test.rs) has 27, and the A6 suites cover machine-mode trap entry and return. No public ELF guest today changes privilege or turns translation on. `exec_mret` (`src/isa/rv64i/system.rs:245-308`) returns to the privilege in MPP, including S, sets MPIE to 1, clears MPRV on a return below M, and calls `state.csr.set_privilege` (`src/isa/rv64i/system.rs:302-303`). `exec_sret` (`src/isa/rv64i/system.rs:319-364`) exists, but the public core reports the SRET encoding as an unsupported legal instruction (`src/core/mod.rs:1522` and `src/core/mod.rs:1543`), so a public guest cannot execute it today. The helper also disagrees with the SRET rule in three places this milestone fixes. It never sets SPIE to 1, where `exec_mret` does set MPIE. It writes `state.privilege` and never calls `state.csr.set_privilege`, so after a return to U the CSR file still checks accesses as S. It returns SEPC unmasked, while MEPC is masked to IALIGN 32 (`src/csr/mod.rs:261-265`).
- **Sv39 components are implemented and component-tested, and they are not integrated.** [`src/mmu/`](../../src/mmu/) parses `satp` (Bare = 0, Sv39 = 8, Sv48 = 9, Sv57 = 10, other values rejected, `src/mmu/mod.rs:127-135`), walks page tables through `PhysicalMemoryInterface`, and defines `MmuError { PageFault, AccessFault, PmpViolation, UnsupportedMode, InvalidSatpMode }`. `Pte` sets and clears A and D. `Mmu::flush_tlb` is labeled an SFENCE.VMA implementation. [`tests/translation_test.rs`](../../tests/translation_test.rs) has 23 tests and [`tests/ad_bits_test.rs`](../../tests/ad_bits_test.rs) has 10. The public core path never calls these. Fetch, load, and store use image-base and storage adaptation. Page-table accesses use the MMU-specific `PhysicalMemoryInterface`, not the A7 and A8 `PhysicalAccess` route. No public instruction decodes or executes SFENCE.VMA. A search for `sfence` under `src/decode`, `src/isa`, and `src/execute` finds nothing. SFENCE.VMA uses the SYSTEM opcode, funct3 = 0, funct7 = `0001001`, and rd = 0. `is_illegal_encoding` sends SYSTEM funct3 = 0 through an allow-list of ECALL, EBREAK, SRET, MRET, and WFI (`src/core/mod.rs:1517-1528`), so every SFENCE.VMA encoding is an illegal-instruction trap today. `Opcode::MiscMem` (`src/decode/mod.rs:39`) is unrelated. It is decoded only as base FENCE (`src/decode/mod.rs:248`).
- **The component walker is not usable on the public path as it stands.** These are defects this milestone fixes, not behavior to preserve.
  - A walk read goes through `PhysicalMemoryInterface::read_dword` (`src/mmu/sv39.rs:313`), and every error becomes `WalkResult::AccessFault { level }` (`src/mmu/sv39.rs:329`). The target, host, protocol, and unknown taxonomy of ADR-0001 and ADR-0002 is lost. The translator then reports `MmuError::AccessFault(vaddr)` (`src/mmu/translator.rs:125`).
  - `VirtualAddress::new` (`src/mmu/sv39.rs:64-83`) rejects a non-canonical virtual address as `MmuError::InvalidVirtualAddress`. That error is neither a page fault nor an access fault, and the translator looks in the TLB before it runs this check (`src/mmu/translator.rs:83`). ADR-0001 §2 and the Sv39 rule both require a page fault of the original access kind, with `mtval` holding the virtual address.
  - The walker checks the reserved permission combination W = 1 and R = 0 (`src/mmu/sv39.rs:356`). It does not check reserved PTE bits 63:54, and it does not check a non-leaf PTE with D, A, or U set. `src/mmu/pte.rs` documents bit 63 as `N` and bits 62:54 as `RSW`, which is not the Sv39 reserved-bit rule.
  - `Sv39::build_physical_address` (`src/mmu/sv39.rs:197-225`) ORs the low VPN fields into the PPN of a 2 MiB or 1 GiB leaf. A misaligned superpage therefore translates instead of raising a page fault.
  - On a TLB hit, `translate_sv39_with_tlb` checks permissions and returns (`src/mmu/translator.rs:83-97`). It never sets D, so a read followed by a write of the same page leaves D clear.
  - `create_tlb_entry` stores `pte.ppn()` and ignores the walk level (`src/mmu/translator.rs:151-173`). A superpage hit then computes `(ppn << 12) | (vaddr & 0xFFF)` and drops VPN[0] for a megapage and VPN[1:0] for a gigapage.
- **PMP is nominal only.** `MmuConfig::pmp_entries` defaults to 16 (`src/mmu/mod.rs:86`) and `MmuError::PmpViolation` exists. There is no `pmpcfg` or `pmpaddr` CSR, no enforcement, and no test. An unknown CSR address returns `CsrError::InvalidAddress` (`src/csr/mod.rs:225-246`), which the core turns into an illegal-instruction trap. Treat PMP enforcement as absent.
- **S-mode CSR state is split, and delegation is inert.** `sstatus` is a separate map entry (`src/csr/mod.rs:162`), not a view of `mstatus`. S-trap entry writes that copy (`src/core/trap.rs:385-389`), and `exec_sret` reads and writes it (`src/isa/rv64i/system.rs:331`). `medeleg` and `mideleg` are stored by the generic CSR write path, and the handler ignores those values. It consults its own `TrapDelegation` (`src/core/trap.rs:315-334`), which the public core leaves at zero. The H-extension `vs*` CSRs are inserted and accept writes (`src/csr/mod.rs:174-182`) even though the hypervisor is a non-goal.
- **The integration seam is the physical port.** A8 and A9 put every fetch, load, store, and AMO through the validated physical data port, with the target, host, protocol, and unknown taxonomy and with the original address preserved in `mtval`. The Hart behind `Machine::step` owns that route. The translator plugs in between the Hart's virtual access and that route. Page-table walks are themselves physical accesses on the same route. `hart_issued_paddr` (`src/core/mod.rs:463`) subtracts `base_addr` from the guest effective address before the port sees it, so translation has to produce a guest physical address before that subtraction.

The milestone wires the existing components through the public path, fixes the walker and fault-classification defects above, adds SFENCE.VMA decode and dispatch, and makes the S-mode CSRs views of the M registers. It is not a from-scratch MMU, and it does not reuse the component walker unchanged.

## 3. Selected scope and exclusions

In scope, from the §8 decisions:

- Privilege modes M, S, and U, with M as the boot mode and the handler mode (D1). A public guest can enter S and U through `mret` and return. SRET becomes a supported instruction in M and in S, and it is illegal in U. `mstatus` bits TVM (20), TW (21), and TSR (22) are writable. With TVM = 1, an S-mode read or write of `satp`, or an S-mode SFENCE.VMA, raises an illegal-instruction exception. With TSR = 1, an S-mode SRET raises an illegal-instruction exception. With TW = 1, a WFI executed in S-mode or U-mode raises an illegal-instruction exception. The spec allows that trap immediately, and this profile takes it immediately rather than waiting out a time limit. When S-mode is implemented, WFI executed in U-mode raises an illegal-instruction exception regardless of TW, unless it completes within an implementation-specific bounded time (privileged specification, `mstatus` TW, norm `mstatus_tw_umode_op`). This profile takes that trap immediately too. The same section permits an immediate illegal-instruction exception, and norm `wfi_resume_reason` permits a completed WFI to be a NOP. All three bits reset to 0. TVM and TSR therefore raise nothing until software sets the bit. U-mode WFI raises illegal-instruction even while TW is 0.
- `satp` modes Bare (0) and Sv39 (8) only (D2). A write whose MODE is anything else, including Sv48 and Sv57, is ignored in full. No field of `satp` changes, and the write raises no trap. MODE changes take effect at the next instruction. ASIDLEN is 0, so the ASID field is read-only zero. `Satp::asid` returning a 16-bit field (`src/mmu/mod.rs:151`) is component behavior, not the public-path width.
- Hart-side translation of instruction fetch, load, store, and AMO effective addresses when the effective privilege mode has Sv39 active (D2, D3). M-mode accesses are not translated unless MPRV applies (D9).
- Each walk step reads one PTE through the existing physical data port (D3). The walk result follows ADR-0001 §2, restated in D3 below. A virtual address whose bits 63:39 are not all equal to bit 38 is a page fault of the original access kind, checked before the walk. The walker rejects reserved PTE bits 63:54, a non-leaf PTE with D, A, or U set, and a misaligned superpage. Sv39 superpage sizes, 2 MiB and 1 GiB, are supported. The component defects in §2 are fixed even though v1 walks on every access, so a later cache cannot inherit them.
- Architectural page faults keep the original virtual access kind and address and use the existing A6 trap entry. No new trap channel.
- Hardware sets A on a completed translation and sets D on a completed store or AMO translation (D4). The write-back is a physical write on the same port. A failed write-back is an access fault of the original access kind. A successful A/D write stays visible in memory. On a retired instruction it is a `MemoryEffect` in `CommitRecord.effects.memory`, and on a faulting instruction it is a `MemoryEffect` in `TrapRecord.effects.memory`.
- No PMP enforcement (D5). `MmuError::PmpViolation` and `MmuConfig::pmp_entries` stay off the public path. The standard RV64 PMP set is implemented as read-only zero. That set is the eight even CSRs `pmpcfg0`, `pmpcfg2`, through `pmpcfg14`, and `pmpaddr0` through `pmpaddr63`. A read returns 0 and a write is ignored. This is the zero-entry PMP the privileged specification allows, chosen so a boot stub that writes any `pmpaddr` or even `pmpcfg` does not trap. Odd `pmpcfg` addresses stay illegal on RV64, as the specification requires.
- Alignment is checked on the virtual effective address before translation (D6). A misaligned instruction fetch, load, store, or AMO raises the misaligned exception and takes priority over a page fault and an access fault. No access splits a page, because the Hart traps every misaligned access (`src/core/mod.rs:980-996`) and IALIGN is fixed at 32.
- No new CLI flag and no new public type (D7). Translation turns on only when the guest writes Sv39 to `satp`, which resets to 0 (`src/csr/mod.rs:171`). The address path is virtual address, then guest physical address from the PTE PPN, then the storage offset `hart_issued_paddr` already applies. A PTE PPN is a guest physical page number, not a storage offset. Walk reads use the same guest-physical path. The old behavior, `satp` stored and ignored, becomes the new behavior, a Sv39 write takes effect and an unsupported MODE is ignored. The one public field this milestone adds is `MemoryEffect.implicit` (D4). Adding it is a breaking change, because `MemoryEffect` is a public struct whose fields are all public and which is not `non_exhaustive` (`src/core/observation.rs:20-30`). A downstream struct literal or an exhaustive destructure stops compiling. The milestone adds no type, no route, and no observation plane.
- SFENCE.VMA is decoded and executed in all four rs1 and rs2 forms (D8). Those are global, per-ASID, per-virtual-address, and one virtual address in one ASID. Every rs1 and rs2 combination with the SFENCE.VMA encoding is legal. With no translation cache (M4) each form is an ordering no-op on the public path. It is legal in M and in S, and illegal in U. An invalid virtual address in `rs1` raises no exception. Other SYSTEM funct3 = 0 encodings stay illegal.
- SUM (`mstatus` bit 18), MXR (bit 19), and MPRV (bit 17) follow the privileged specification (D9). With SUM = 0, an S-mode load or store to a U = 1 page is a page fault. MXR = 1 lets a load read an X = 1 page. S-mode fetch of a U = 1 page is a page fault regardless of SUM. MPRV = 1 makes a load or store use the translation and protection of MPP, and it does not affect instruction fetch. SUM still applies when MPRV = 1 and MPP = S. `mret` and `sret` clear MPRV whenever the return privilege is below M. SPP is one bit, so SRET always returns below M. `exec_mret` already clears MPRV for `mret`.
- No trap delegation (M1). `medeleg` and `mideleg` are read-only zero. Every synchronous exception, including every page fault, is taken in M, and `mtvec`, `mepc`, `mcause`, and `mtval` record it. The writable `TrapDelegation` in `src/core/trap.rs` is not a public-path control. A pending and enabled supervisor interrupt is also taken in M (D11).
- `sstatus`, `sie`, and `sip` are restricted views of `mstatus`, `mie`, and `mip` (M2). A write through either address changes the one register, and a read through either address returns that register's S-visible fields. The separate `sstatus` storage (`src/csr/mod.rs:162`) goes away. `misa` reports M (12), A (0), I (8), S (18), and U (20), and each of those bits is read-only 1. F (5), D (3), C (2), and H (7) are read-only 0. The F, D, Zfinx, Zfh, and V extensions are not implemented, and Stage 4 does not claim them. `mstatus.FS` is read-only 0 (20250508 machine, "If S-mode is implemented but the F extension is not, FS may optionally be read-only zero"). With FS, VS, and XS all read-only 0, SD is read-only 0 ("If FS, VS, and XS are all read-only zero, then SD is also always zero"). SXL and UXL are read-only 2. Reset `mstatus` is `0x0000_000A_0000_0000` and reset `sstatus` is `0x0000_0002_0000_0000`. Every encoding whose major opcode is LOAD-FP (`0x07`), STORE-FP (`0x27`), OP-FP (`0x53`), MADD (`0x43`), MSUB (`0x47`), NMSUB (`0x4B`), or NMADD (`0x4F`) raises illegal-instruction in every mode, for every `funct3` and every `rm`. `mtval` holds the instruction bits. The check runs before the data alignment check, before a data page-table walk, and before any physical data request. Fetch of the instruction itself still walks and still issues its fetch request when Sv39 is on. The trap has no data memory effect, no A or D write, no FPR effect, and no FCSR effect. `fflags`, `frm`, and `fcsr` (`0x001` through `0x003`) do not exist, and any access raises illegal-instruction. The H-extension `vs*` CSRs (`src/csr/mod.rs:174-182`) are removed from the public CSR file, so a write to one is an illegal-instruction trap instead of a stored value. `menvcfg` (`0x30A`) and `senvcfg` (`0x10A`) exist. Neither address is in `CsrFile::new` today (`src/csr/mod.rs:140-182`), so access is an illegal-instruction trap. `mvendorid`, `marchid`, `mimpid`, and `mconfigptr` exist and read 0. `mcycle` counts completed cycles, and `minstret` counts retired instructions. `mhpmcounter3` through `mhpmcounter31` and `mhpmevent3` through `mhpmevent31` exist and read 0. The field rules for every S-profile CSR this milestone exposes are the M2 table. Stage 4 replaces the generic CSR write (`src/csr/mod.rs:276-278`) and the current `mstatus` and `misa` masks for each row of that table.
- No translation cache on the public path (M4). Every translated access walks. The component TLB stays a component, and its two defects in §2 are fixed so the component tests stop encoding them. Roadmap Stage 4's "TLB integration" deliverable is deferred to a later milestone and recorded as such.

Non-goals: hypervisor and the H extension, including `hgatp` and the `vs*` CSRs; Linux or SBI boot; multi-hart TLB coherence; a translation cache on the public path; instruction-cache or data-cache modeling; performance work on the walk; debug-mode interaction with translation; any change to A8 atomic semantics; Sv48 and Sv57; PMP enforcement beyond the read-only-zero CSRs; trap delegation; a WFI that stalls the hart; the F and D extensions, which a later milestone adds as a new IEEE-754 feature and which Stage 4 does not claim; `mcountinhibit` (D10); a platform interrupt controller, a memory-mapped timer, and any interrupt other than the three supervisor causes in D11. No new public type and no CLI change. The one public field added is `MemoryEffect.implicit` (D4), and adding it is the breaking change D7 records.

## 4. Workload and oracle contract

Every fixture below is part of the milestone. The oracle shape follows A10. Each fixture records source, linker, and ELF SHA-256, producer identities, exact instruction, retirement, and trap counts, and complete effect expectations. A trap-inclusive fixture reports attempts, completed turns, traps, and retirements independently. `ExecutionResult.cycles` includes completed trap turns. No guest writes MINSTRET, except the identity-and-counters fixture, which writes a chosen value to `mcycle` and to `minstret` and reads that value back.

## 5. Route and phase matrix

Reuse the A10 route matrix. Translation adds no new route and no new configuration cell. `satp` resets to 0, so every existing fixture stays bare without a new Machine or CLI input (D7). A10 baseline and smoke commands gain no mandatory cell from this contract. Timing of a translated path is not an acceptance criterion.

Observation stays on the existing path (D4). A faulting instruction produces a `TrapRecord` and no `CommitRecord` (`Observation::build`, `src/core/observation.rs:131-195`). ADR-0001 §2 already allows a profile-mandated effect of a faulting attempt to be visible, and line 74 of that ADR says a successful A/D write is not rolled back and is not included as a retired effect.

The profile states where the effect is recorded.

- When the instruction retires, the A/D update is a `MemoryEffect` in `CommitRecord.effects.memory`. It is ordered before the explicit load, store, or AMO. `MemoryEffect.implicit` is true for that page-table write and false for the explicit access.
- When the A/D write succeeds and the instruction then faults, the same `MemoryEffect` is carried in `TrapRecord.effects.memory`. The instruction has no `CommitRecord`. The bytes in memory stay updated.

`MemoryEffect` (`src/core/observation.rs:20-30`) has no such field today. This milestone adds `implicit: bool` to that struct. The Hart sets it when it records an A/D write, and leaves it false for every other memory effect. No new type, no new observation record, and no new observation plane. The guest-address and width fields stay as they are, so an observer that ignores `implicit` still sees the same bytes. The struct is public, every field is public, and it carries no `non_exhaustive` attribute, so the added field is a breaking change for a downstream struct literal or an exhaustive destructure. D7 records that change.

**D1. Privilege levels in v1.** DECIDED, option A. A public guest runs in M, S, and U and can transition among them. M is the boot mode and the handler mode. This matches the existing `PrivilegeMode` and the A6 trap machinery, and it adds no new privilege state. `mret` to MPP = S and `sret` already exist (`src/isa/rv64i/system.rs:245` and `src/isa/rv64i/system.rs:319`). Making SRET executable on the public path is part of this decision. So is closing the S-mode gaps that M1 and M2 record. `sstatus` is stored separately today, and `medeleg` and `mideleg` writes are stored and ignored.

TVM, TSR, and TW are writable because S-mode exists and `satp`.MODE is writable. Privileged-specification norm `mstatus_tvm_acc` says TVM is read-only 0 only when S-mode is absent or `satp`.MODE is read-only 0, and otherwise must be writable. Norms `mstatus_tsr_acc` and `mstatus_tw_acc` say the same for TSR and TW once a mode below M exists. The current mask `0x8000_0003_000F_FFEA` (`src/csr/mod.rs:272`) excludes bits 20, 21, and 22, so all three read as zero today. That changes.

The trap effects follow the same section. Norm `mstatus_tvm_op` says TVM = 1 makes an S-mode read or write of `satp`, or an S-mode SFENCE.VMA, raise illegal-instruction. Norm `mstatus_tsr_op` says TSR = 1 makes an S-mode SRET raise illegal-instruction. Norm `mstatus_tw_op` says TW = 1 makes a WFI in a mode below M raise illegal-instruction when the instruction does not finish within an implementation-specific time limit, and norm `mstatus_tw_always_illegal` allows the implementation to raise that exception immediately. This profile raises it immediately. Norm `mstatus_tw_umode_op` says that, when S-mode is implemented, WFI in U-mode raises illegal-instruction regardless of TW unless it completes within an implementation-specific bounded time. This profile raises that exception immediately as well. D10 states the WFI rule for every mode. Machine mode is unaffected by all three bits, and each bit resets to 0. The §4 fixture covers each bit from S-mode, both U-mode WFI cases, and the machine-mode case.

- Option A, chosen. M, S, and U, with M as the boot and handler mode.
- Option B, rejected. M and U without S is not a standard paging configuration, because `satp` is an S-mode CSR.
- Option C, rejected. M-mode accesses are never translated except through MPRV, so M alone cannot exercise translation.

**D2. `satp` modes.** DECIDED, option A, with the rejection rule stated as WARL. The public path implements Bare (0) and Sv39 (8). A write with any other MODE is ignored in full. No field changes and no trap is raised. This is the rule in privileged-specification norm `satp_mode_op_unsupported`. Translation changes apply at the next instruction. ASIDLEN is 0, which the same specification explicitly allows, so the ASID field is read-only zero. The component parser accepts Sv48 and Sv57 as well (`src/mmu/mod.rs:127-135`). That acceptance is not a public-path commitment, and the public write path filters those modes out.

- Option A, chosen. Bare and Sv39 only, with an unsupported MODE ignored in full.
- Option B, rejected. Storing Sv48 and behaving as Bare would report a mode the core does not implement.
- Option C, rejected. Implementing Sv48 is larger than this milestone.

**D3. Sv39 page-table walk.** DECIDED, option A, rewritten so the fault rule matches ADR-0001 §2. Each walk read is a physical data read on the existing A7 and A8 port. The result of that read is classified as follows.

| Walk condition | Result |
| --- | --- |
| The target rejects the walk read, or the target rejects the A/D write-back | Access fault of the original access kind. Cause 1 for a fetch, 5 for a load, and 7 for a store or AMO. |
| The completion is a host, protocol, or unknown failure | `SimulatorFailure`. Never an access fault and never a page fault. |
| The virtual address is not canonical. Bits 63:39 are not all equal to bit 38. | Page fault of the original access kind, raised before the walk. Cause 12 for a fetch, 13 for a load, and 15 for a store or AMO. |
| The PTE is invalid (V = 0), has W = 1 and R = 0, or has a reserved bit 63:54 set | Page fault of the original access kind. Same causes as the row above. |
| The walk ends without a leaf, the PTE is a non-leaf with D, A, or U set, or the leaf is a misaligned superpage | Page fault of the original access kind. |
| The leaf fails the U, SUM, or MXR check | Page fault of the original access kind. |
| The leaf fails the R, W, or X check for the access | Page fault of the original access kind. |

The rows follow the Sv39 walk order. The non-canonical check comes before step 2. Step 2 is the access fault on the PTE read. Steps 3 through 5 cover an invalid PTE, a reserved PTE, a missing leaf, and a misaligned superpage. Step 6 is the U, SUM, and MXR check. Step 8 is the R, W, and X check. Step 9 is the A and D write. `mtval` holds the original virtual address in every guest-visible case. The walk level and the PTE address may be kept as diagnostics, and they do not replace `mtval`. Sv39 superpages, 2 MiB and 1 GiB, are supported. The component walker does not implement this rule today. It collapses every read error into one access fault, it reports a non-canonical address as `InvalidVirtualAddress` (`src/mmu/sv39.rs:64-83`), and it misses the reserved-bit and misaligned-superpage checks (§2). Those are in-scope fixes.

- Option A, chosen, with the table above replacing the earlier "a failed walk read is the guest's page fault" wording.
- Option B, rejected. Leaving walks on the MMU-private `PhysicalMemoryInterface` would keep page-table reads off the A7 and A8 taxonomy, which the roadmap forbids.
- Option C, rejected. A software-managed walk cache is an optimization, and M4 already declines a translation cache.

**D4. A/D bit policy.** DECIDED, option A. Hardware sets A on a completed translation and sets D on a completed store or AMO translation. The write-back is a visible physical write on the same port as the walk. A failed write-back is an access fault of the original access kind, per ADR-0001 §2, not a page fault and not a dropped write. A successful A/D write is a separate physical effect. If the access that required it later faults, the write is not rolled back. The instruction has no `CommitRecord`, and the write is recorded in `TrapRecord.effects.memory`. Its memory effect stays visible (ADR-0001 §2, the paragraph at line 74 of `docs/architecture/decisions/0001-hart-execution-outcome-and-observation.md`). The component already sets A and D on the walk path (`src/mmu/sv39.rs:450-510`) and fails to set D on a TLB hit (`src/mmu/translator.rs:83-97`). The TLB-hit defect is fixed even though the public path does not cache.

The A/D write is told apart from the explicit access by `MemoryEffect.implicit`. That field does not exist on `MemoryEffect` today (`src/core/observation.rs:20-30`, public through `pub mod observation` at `src/core/mod.rs:6`). This milestone adds the field. `implicit` is true only for the page-table write that sets A or D, and false for every other `MemoryEffect`. No new observation type is added. The struct is public, every field is public, and it is not `non_exhaustive`, so the added field breaks a downstream struct literal or an exhaustive destructure. D7 records the field as the one public addition and as that breaking change.

- Option A, chosen. Hardware sets A and D, with the fault and observation rules above.
- Option B, rejected. Trapping on a clear A or D bit adds a trap handler to every v1 fixture.
- Option C, rejected. A per-Machine flag is a second configuration with no consumer.

**D5. PMP entries and granularity.** DECIDED, option A, plus a defined CSR behavior. There is no PMP enforcement in this milestone. `MmuError::PmpViolation` and `pmp_entries` stay off the public path. The exclusion is a non-goal in §3. Because a zero-entry PMP is a conforming choice, the standard RV64 PMP set is implemented as read-only zero. Norm `pmp_cfg_rv64_layout` names that set as the eight even CSRs `pmpcfg0`, `pmpcfg2`, through `pmpcfg14`, and norm `pmp_addr_registers` names `pmpaddr0` through `pmpaddr63`. A read returns 0 and a write changes nothing and raises nothing. Norm `pmp_entry_count` allows zero entries, and norm `pmp_csrs_warl_access` allows the fields to be read-only zero. The spec does not say which addresses exist when the entry count is zero, and norm `Zicsr_nonexistent_rsv` reserves access to an address the hart does not implement. Exposing the whole standard set is the implementation choice, so no guest-visible boundary sits at entry 16 on a hart with no entries. This is the behavior recorded so a boot stub that writes any `pmpaddr` or even `pmpcfg` before `mret` does not trap. Today those addresses are absent, and an unknown CSR returns `InvalidAddress` (`src/csr/mod.rs:225-246`), which becomes an illegal-instruction trap. Odd `pmpcfg` numbers stay illegal on RV64 (norm `pmp_cfg_rv64_illegal`).

- Option A, chosen. No enforcement, with the read-only-zero CSRs above.
- Option B, rejected. Eight enforced entries is a larger milestone. Its granularity note was also wrong. NA4 and TOR allow 4 bytes, and NAPOT starts at 8 bytes.
- Option C, rejected. Sixteen enforced entries plus `mseccfg` is larger than v1.

**D6. Fault and trap behavior, including misaligned access.** DECIDED, option A, restated. The Hart checks alignment on the virtual effective address before translation, and the misaligned exception takes priority over a page fault and an access fault. This is the check already at `src/core/mod.rs:980-996` for a load, a store, and an AMO, extended to a translated access without changing the order. IALIGN is fixed at 32 and C is forced off in `misa` (`src/csr/mod.rs:255-260`), so no access can cross a 4 KiB page. The page-split sentence in the earlier option A described a case the core cannot reach, and the roadmap already lists successful misaligned accesses as a non-goal. Page faults use the existing cause codes and the existing `mtval` path. No new trap channel is added.

- Option A, chosen, in the restated form. No page-split behavior is specified, because no access splits a page.
- Option B, rejected as a change. The core already traps every misaligned access the RAM path could see, so there is no second population to add.
- Option C, rejected. Two alignment policies would contradict the single check the core already has.

**D8. TLB invalidation.** DECIDED, option A, read together with M4. SFENCE.VMA is decoded and executed in all four forms the supervisor chapter names. Both registers x0 orders every address space (`sfence_vma_all_asid_va`). rs1 = x0 with rs2 not x0 orders one ASID (`sfence_vma_asid_only`). rs1 not x0 with rs2 = x0 orders one virtual address in every ASID (`sfence_vma_va_all_asid`). Neither register x0 orders one virtual address in one ASID (`sfence_vma_va_asid`). Every rs1 and rs2 value is legal with this encoding. It is legal in M and in S and illegal in U.

Only funct7 = `0001001` with rd = 0 is SFENCE.VMA. The instruction uses the SYSTEM opcode, not MISC-MEM. Any other SYSTEM funct3 = 0 encoding stays an illegal instruction, which is what `is_illegal_encoding` does today for everything outside its allow-list (`src/core/mod.rs:1517-1528`). Because M4 puts no translation cache on the public path, the fence has no cache entry to invalidate and is an ordering no-op there. The architectural requirement is the one the specification states. A translation written before the fence is the translation used after the fence. The fixture records the pre-fence behavior as a property of this model. All three bits are already writable (`MSTATUS_MASK_RV64 = 0x8000_0003_000F_FFEA`, `src/csr/mod.rs:272`), and the component ignores them. `walk_check_permissions` lets S-mode reach a U = 1 page and says so (`src/mmu/sv39.rs:380-392`). Leaving the bits writable and ignored would be option C, which is rejected. With S-mode implemented, SUM and MXR are required to be writable unless `satp`.MODE is read-only zero, which D2 forbids. MPRV is how M-mode code, the handler mode, reads and writes a guest virtual address. `mret` already clears it on a return below M (`src/isa/rv64i/system.rs:285-293`). SUM applies to those accesses when MPP = S (norm `mstatus_sum_op_mprv_mpp`), and the MPRV fixture covers that case. SPP is one bit (norm `mstatus_spp_sz`), so an SRET always returns below M and always clears MPRV. The privilege-transition fixture in §4 is what checks it.

- Option A, rejected. The bits cannot stay writable and also stay inert, and hardwiring them to zero is not available while S-mode exists and `satp` is writable.
- Option B, chosen, plus MPRV.
- Option C, rejected. A writable SUM, MXR, or MPRV bit that software sets and the hart then ignores does not implement the privileged specification.

**D10. WFI and counters.** DECIDED for WFI, for the two basic counters, and for the 29 additional counters as read-only zero. WFI follows the privileged specification, as the rest of this decision states. Interrupt delivery is D11, and D11 is decided. Traps this decision itself adds are the synchronous WFI traps below. A faulting instruction does not retire (ADR-0001 §2, line 56), and the A10 oracles already count traps separately from retirements.

`mcycle` (`0xB00`) and `minstret` (`0xB02`) are both implemented. The 20250508 machine chapter, Hardware Performance Monitor, says the `mcycle` CSR counts the clock cycles executed by the processor core and the `minstret` CSR counts the instructions the hart has retired, gives both 64-bit precision on every RV64 hart, and says the counter registers hold an arbitrary value after reset and can be written. `minstret` already exists and increments by one for each retired instruction (`src/csr/mod.rs:322`, called from `src/core/mod.rs:1118`). `mcycle` does not exist, and a read of it is an illegal-instruction trap today. This milestone adds it. `mcycle` counts the clock cycles the core completes, and it advances by the cycles of each completed Hart turn, including a turn that takes a trap and retires nothing. A write to either counter takes effect after the writing instruction has otherwise completed. Both reset to 0, which the arbitrary reset value allows. `cycle` (`0xC00`) and `instret` (`0xC02`) are the read-only shadows of `mcycle` and `minstret`. Because `mcounteren` stays read-only 0, an S-mode or U-mode read of `cycle` or `instret` raises illegal-instruction. `mcountinhibit` is not implemented, so the hart behaves as though it were zero and both counters always increment. The same section says that if `mcountinhibit` is not implemented, the implementation behaves as though the register were set to zero.

The same section says the hardware performance monitor includes 29 additional 64-bit event counters, `mhpmcounter3` through `mhpmcounter31`, and that a legal implementation is to make both the counter and its corresponding event selector read-only 0. This profile takes that implementation. `mhpmcounter3` through `mhpmcounter31` (`0xB03` through `0xB1F`) and `mhpmevent3` through `mhpmevent31` (`0x323` through `0x33F`) exist, read 0, and ignore a write. The write raises no trap. The unprivileged `hpmcounter3` through `hpmcounter31` (`0xC03` through `0xC1F`) stay absent, and an access raises illegal-instruction. Zihpm is not claimed. Its rule allows an unimplemented unprivileged counter to raise illegal-instruction, and absence is that choice.

`time` (`0xC01`) is not added, because this profile has no `mtime`. The Zicntr extension comprises `cycle`, `time`, and `instret` together (20250508 unprivileged counters, "The Zicntr standard extension comprises the first three of these counters"). This profile implements `cycle` and `instret` and does not implement `time`, so it does not claim Zicntr. A read of `time`, in any mode, raises illegal-instruction. `rdtime` is that read.

WFI follows the privileged specification rather than the current report of an unsupported legal instruction (`src/core/mod.rs:1543-1544`). Norm `wfi_all_privileged_modes` makes WFI available in M, and norm `wfi_resume_reason` permits an implementation to execute it as a NOP. In M-mode, WFI retires as a NOP, whether TW is 0 or 1. PC advances by 4, and `minstret` and `mcycle` count the retirement. No other architectural state changes. In S-mode with TW = 0, WFI does the same. Norm `mstatus_tw_op`, read with norm `mstatus_tw_always_illegal`, permits an immediate illegal-instruction exception for WFI below M when TW = 1. This profile takes that trap immediately in S-mode. Norm `mstatus_tw_umode_op` requires the same exception for WFI in U-mode whenever S-mode is implemented, regardless of TW, unless the instruction completes within an implementation-specific bounded time. This profile does not complete U-mode WFI. It raises illegal-instruction immediately at TW = 0 and at TW = 1. The §4 fixture executes WFI in S-mode at both TW values, in U-mode at both TW values, and in M-mode with TW = 1. A WFI that stalls the hart stays with Stage 5, as §9 records.

- WFI and the two basic counters, chosen, as stated above. The earlier wording that also chose "no interrupt is delivered" is withdrawn. Delivery of the supervisor causes is D11. The earlier wording that added no counter rule is also withdrawn. `mcycle` and `minstret` are mandatory, and this decision implements both.
- A machine timer interrupt, and a supervisor timer interrupt raised by `stimecmp` or `mtime`, stays out of this milestone. D11 makes STIP a software-written bit because Sstc is absent. It does not add a timer.
- `mcountinhibit` and `time` stay out. The 29 additional counters are implemented as read-only 0, which is the legal floor, and their unprivileged shadows stay absent. The read-only-zero rule applies to the additional counters and not to `mcycle` or `minstret`, so leaving those two absent is not available.

**D11. Supervisor interrupt bits and delivery.** DECIDED, option (a). `mip` and `mie` are fully writable today (`src/csr/mod.rs:151`, `src/csr/mod.rs:159`, and the generic arm at `src/csr/mod.rs:276-278`). The public core has no interrupt-taking path. This decision adds both the field rule and the delivery rule. Privileged specification 20250508 §3.1.9 is the source. With S-mode implemented, SSIP, STIP, and SEIP are writable in `mip` (norms `mip_ssip_acc`, `mip_stip_no_stimecmp_acc`, and `mip_seip_acc`). `stimecmp` is absent, so the STIP sentence applies. A `mie` bit is writable when the matching interrupt can become pending (norm `mie_bits_wr`), so SSIE, STIE, and SEIE are writable. The write mask for both registers is `0x222`.

MEIP, MTIP, and MSIP are read-only in `mip` (norms `mip_meip_rdonly`, `mip_mtip_rdonly`, and `mip_msip_rdonly`). This hart has no platform interrupt controller and no memory-mapped timer compare, so each of those bits reads 0. The matching enables MEIE, MTIE, and MSIE are read-only 0 (norm `std_mach_intr_impl`). LCOFIP and LCOFIE are read-only 0 because Sscofpmf is absent. No other `mip` or `mie` bit is writable. A write of a read-only bit leaves it 0 and raises no trap. There is no PLIC, so the external signal that the SEIP rule ORs with the software-written bit is 0. A read of SEIP returns the software-written bit. CSRRS and CSRRC use that same software-written bit, not an external signal.

`mideleg` stays 0 (M1), so every interrupt that is taken is taken in M. An interrupt i is pending when bit i is set in `mip & mie & ~mideleg`. It is taken when that value is nonzero and either the privilege is below M, or the privilege is M and `mstatus.MIE` is 1 (norm `intr_mip_mie_op`). SIE does not gate a trap into M (norm `mstatus_xie_intr_en_dis`). The hart checks this at each instruction boundary, and it checks again immediately after MRET or SRET and after an explicit write to `mip`, `mie`, `mstatus`, or `mideleg`, including a write through `sstatus` (norms `intr_mip_mie_bounded_time` and `intr_mip_mie_xret_csrwr`). Among causes pending together, the order is MEI, MSI, MTI, SEI, SSI, STI (norm `intr_m_mode_pri`). MEI, MSI, and MTI cannot become pending here, so the order in this profile is SEI (9), SSI (1), STI (5).

The taken trap uses the existing M-mode trap entry. `mcause` is `(1<<63)` with the cause code in the low bits (norm `mcause_intr_op`). `mepc` is the virtual address of the interrupted instruction (norm `mepc_op`). `mtval` is 0 (norm `mtval_other_traps_zero`). MPIE receives MIE, MIE becomes 0, and MPP records the privilege that was interrupted (norm `mstatus_xpie_xie_xpp_trap_op`). Privilege becomes M. With `mtvec` MODE 0 (Direct), PC becomes BASE. With MODE 1 (Vectored), PC becomes BASE plus 4 times the cause code (norms `mtvec_mode_direct_op` and `mtvec_mode_vectored_op`). The entry consumes one completed Hart turn and does not retire an instruction (ADR-0001 and ADR-0004 §3.1). WFI stays the NOP in D10. That is a legal implementation (norm `wfi_resume_reason`), and this milestone does not add a stall.

Spike at `d6cfe9ef` writes SSIP, STIP, and SEIP in `mip` when S-mode is present and Sstc is off (`riscv/csrs.cc` lines 993 through 1020). Sail at `6136f843` legalizes the same three bits in `legalize_mip` and `legalize_mie` (`model/core/interrupt_regs.sail` lines 58 through 120). Spike also leaves MEIE, MTIE, and MSIE writable because it has a CLINT and a PLIC. This hart has neither, so those three enables stay read-only 0. The analysis is `050-Agents/dragonite/2026-10-10 RISC-V mip-mie B5.md`.

ADR-0004 §17 leaves the pending, enable, and priority predicate to the selected Hart profile. This decision is that predicate for the Stage 4 profile. It does not add a Platform source, a controller, `mtime`, or a Machine idle jump. Those stay with roadmap Stage 5. The amendment in ADR-0004 §17 records the same split. Writable supervisor bits that are never delivered would violate norm `intr_mip_mie_op`, so delivery is in this milestone rather than deferred.

`sip` and `sie` stay the read-only-zero views M2 already states, because `mideleg` stays 0. D7 records the `mip` and `mie` change, including the two CSR tests that currently expect a full write to read back.

- Option (a), chosen. The field rule and the delivery rule above.
- Option (b), rejected. The 20250508 supervisor chapter does allow it. The sentence reads "Each standard interrupt type (SEI, STI, SSI, or LCOFI) may not be implemented, in which case the corresponding interrupt-pending and interrupt-enable bits are read-only zeros." A later revision says "might not" for the same rule. Read-only zero for SSIP, STIP, and SEIP would therefore conform. This profile does not take that allowance. With S-mode implemented and no Sstc, the 20250508 `mip` rules make SSIP, STIP, and SEIP writable, and option (a) follows those sentences. Writable bits that are never delivered would violate the rule that a pending enabled interrupt is taken, so the delivery rule is part of the same decision.

**M1. Trap delegation.** DECIDED. No trap delegation in v1. `medeleg` and `mideleg` are read-only zero, and every synchronous exception, including every page fault, is taken in M. Norm `medeleg_mideleg_mandatory_s_mode` requires both registers to exist once S-mode exists. The privileged specification makes them WARL (norm `medeleg_mideleg_warl`) and forbids read-only one (norms `medeleg_no_rd1` and `mideleg_no_rd1`). Read-only zero is the subset it allows, and writing ones and reading them back returns zero, which is how software discovers that subset. The current code stores the writes and ignores them (`src/csr/mod.rs` generic insert, `src/core/trap.rs:315-334`). After this milestone the writes do not change the value.

**M2. S-mode CSR fidelity.** DECIDED. `sstatus` is a restricted view of `mstatus`, and `sie` and `sip` are restricted views of `mie` and `mip`. The privileged specification states each of those directly (machine chapter on `mstatus`, supervisor chapter on `sstatus`, `sip`, and `sie`). One register is stored. The S-mode address reads and writes only the S-visible fields, and the M-mode address reads and writes the whole register. The SXLEN-64 `sstatus` layout shows SIE, SPIE, UBE, SPP, VS, FS, XS, SUM, MXR, and SD, plus UXL when SXLEN is 64. SPELP and SDT appear in that layout only when Zicfilp and Ssdbltrp are implemented, and both are absent here, so those bits read 0. TVM, TSR, TW, MPRV, MPP, MPIE, and MIE are not in that layout, so an S-mode write cannot change them. The separate `sstatus` storage (`src/csr/mod.rs:162`) is removed, and S-trap entry and `sret` stop using it.

With `mideleg` held at 0 by M1, no interrupt is delegated, so every bit of `sip` and `sie` is read-only zero. The machine chapter states that directly. A bit becomes visible in `sip` and writable in `sie` only when the matching `mideleg` bit is set, and no such bit is set here. The write behavior of `mip` and `mie` is the D11 rule and the `mip` and `mie` row below.

`misa` reports every standard extension the public path executes, and none of those bits is writable. The 20250508 machine chapter requires the maximal supported set in the Extensions field at reset, and it allows a writable bit only where the implementation lets software change the supported ISA. This profile does not. The reset value is `0x8000_0000_0010_0100` today (`src/csr/mod.rs:148`), which sets I and U and leaves M, A, and S clear. The new reset value is `0x8000_0000_0014_1101`. Bit 20 is U, bit 18 is S, bit 12 is M, bit 8 is I, and bit 0 is A. F (5), D (3), C (2), and H (7) are read-only 0. C stays 0, so IALIGN stays 32. The same chapter says M = 1 means the hart supports every multiply and divide instruction of the M extension, so the five word instructions the executor drops today are completed rather than left failing. F and D stay clear because the public path does not implement those extensions. The dependency rule, which clears D when F is clear, is satisfied by both bits reading 0. The current write stores every bit except C (`src/csr/mod.rs:255-260`). That stops, and D7 records the change.

SXL and UXL read 2 and ignore writes. For an RV64 hart, norm `mstatus_sxl_acc_mxlen64` makes SXL a WARL field encoding SXLEN once S-mode exists, and 0 is not an encoding. Norm `mstatus_uxl_acc_mxlen64` says the same for UXL once U-mode exists, and today bits 33:32 are writable and reset to 0. Norms `mstatus_sxl_rdonly_mxlen64` and `mstatus_uxl_rdonly_mxlen64` allow both fields to be read-only, and the MXL encoding table (`misa_mxl_enc`) gives 2 for XLEN 64. The current mask excludes bits 35:34, so SXL is already read-only, but it reads 0. Both fields read 2.

The same mask, `0x8000_0003_000F_FFEA` (`src/csr/mod.rs:272`), and the generic write arm (`src/csr/mod.rs:276-278`) store other values the privileged specification does not allow in this profile. SD is writable, and the 20250508 machine chapter makes it read-only. Its value is the dirty summary, set when FS, VS, or XS encodes Dirty. VS is writable, and the same chapter permits read-only 0 when S-mode exists and the V registers are absent. This profile takes that permission. XS is writable, and the chapter makes it read-only 0 because no added user extension has state. FS is writable and resets to 0, which is Off. The F extension is not implemented and S-mode is, so the same chapter permits FS to be read-only zero. This profile takes that permission. FS reads 0 and ignores writes, through `mstatus` and through `sstatus`. Spike keeps FS writable whenever S is present (`riscv/csrs.cc`, `has_fs` true when S or F is enabled), so a differential against Spike masks FS and does not treat a writable FS as a failure of this profile. With FS, VS, and XS all read-only 0, the SD rule makes SD read-only 0 as well. There is no floating-point state to mark Dirty, so this profile states no Dirty transition. UBE is writable, and this hart performs no big-endian U-mode access, so read-only 0 satisfies the endian field rule. SBE and MBE are already outside the mask, so they already read 0. MPP accepts 2, and the chapter allows only M and the implemented modes below M. `sepc` is stored unmasked, while the chapter requires bits 1:0 to read 0 when IALIGN is fixed at 32. `stvec` and `mtvec` accept a reserved MODE. `mcounteren` and `scounteren` store 64 bits, and both registers are 32 bits wide. `menvcfg` and `senvcfg` are absent. Stage 4 fixes every one of those writes. The table is the rule.

The F, D, Zfinx, Zfh, and V extensions are not implemented, and `misa` does not claim F or D. Every encoding with major opcode LOAD-FP (`0x07`), STORE-FP (`0x27`), OP-FP (`0x53`), MADD (`0x43`), MSUB (`0x47`), NMSUB (`0x4B`), or NMADD (`0x4F`) raises illegal-instruction in every privilege mode, for every `funct3` and every rounding mode. `mtval` holds the instruction bits, which is the value `enter_trap` already records (`src/core/mod.rs:964-971`). The synchronous-exception priority table places an illegal instruction above address translation, and it places a misaligned load or store at an optional slot that applies only once the instruction is a memory access. This check therefore runs before the data alignment check, before a data page-table walk, and before any physical data request. Fetch of the instruction still walks and still issues its fetch request when Sv39 is on. The trap record shows no data memory effect, no data walk read, no A or D write, and no FPR or FCSR effect. The Hart change from today is that `is_illegal_encoding` returns true for `LoadFp`, `StoreFp`, and `OpFp`, including the widths it currently accepts. `src/core/mod.rs:1529` covers the LOAD-FP and STORE-FP widths, and `src/core/mod.rs:1536` is the arm that already treats every other opcode, including OP-FP, as legal. The four FMA opcodes are already absent from `Opcode` (`src/decode/mod.rs:34-52`), so they already take this trap. Zfinx is not implemented, so no floating-point CSR exists in its place.

FENCE.I raises illegal-instruction. The profile is RV64IMA plus Zicsr, and it does not claim Zifencei. The 20250508 unprivileged chapter "Zifencei" Extension for Instruction-Fetch Fence defines FENCE.I, and the base I chapter defines FENCE and not FENCE.I. The 20250508 machine chapter, under `misa`, says that when a feature is not implemented, the corresponding opcodes and CSRs become reserved, not necessarily illegal. A reserved encoding may trap. This profile takes the illegal-instruction trap for every FENCE.I encoding, in every privilege mode, with `mtval` holding the instruction bits. It does not report FENCE.I as a legal unimplemented instruction. The current decoder returns `DecodeError::UnimplementedInstruction` for MISC-MEM funct3 = 1 (`src/decode/mod.rs:254-257`), and the Hart reports that as `UnsupportedLegalInstruction` (`src/core/mod.rs:955-959`). That report is the behavior this milestone replaces. Claiming Zifencei was the other conforming choice. On this one hart, with no instruction cache, a FENCE.I that retires and changes nothing would match the Zifencei rule that a subsequent fetch sees earlier stores. This profile does not take that choice, because the stated ISA is RV64IMA plus Zicsr and `misa` has no Zifencei bit to set. The D7 inventory names every test that pins the old report.

The M extension is completed. `is_illegal_encoding` accepts the `Opcode::Op32` pairs `(funct3, funct7)` of `(0, 1)`, `(4, 1)`, `(5, 1)`, `(6, 1)`, and `(7, 1)` (`src/core/mod.rs:1513`), and the `Op32` dispatcher never executes them. Those five are MULW, DIVW, DIVUW, REMW, and REMUW. The eight 64-bit M instructions and every legal AMO, LR, and SC already execute, so they need no new operation.

`fflags` (`0x001`), `frm` (`0x002`), and `fcsr` (`0x003`) do not exist. Any access, in any mode, raises illegal-instruction. That is the reserved-access rule for a CSR address the hart does not implement, the same rule this profile uses for the `vs*` addresses. The addresses are already absent today (`CsrError::InvalidAddress`), so the rule needs no new CSR. They are not gated by FS, because FS is read-only 0 and the registers are not present.

`mvendorid` (`0xF11`), `marchid` (`0xF12`), `mimpid` (`0xF13`), and `mconfigptr` (`0xF15`) are added as read-only zero. Each must be readable (norms `mvendorid_always_rd`, `marchid_always_rd`, `mimpid_always_rd`, and `mconfigptr_mandatory`), and zero is a permitted value for each (those three norms, and norm `mconfigptr_val`). `mvendorid` is 32 bits. `marchid` and `mconfigptr` are MXLEN bits. The text states no width for `mimpid`, and the register reads 0. A write to any of the four raises illegal-instruction (norm `Zicsr_illegal_acc`). `mcycle`, `minstret`, `cycle`, and `instret` follow D10.

`menvcfg` is mandatory because this hart has U-mode (norm `menvcfg_mandatory_u_mode`). `senvcfg` is the SXLEN-bit supervisor environment register (norm `senvcfg`, address `0x10A`). FIOM cannot be read-only zero here. Norm `menvcfg_fiom_rdonly0_ok` allows that only when S-mode is absent or `satp`.MODE is read-only zero, and norm `senvcfg_fiom_acc` has the same `satp` condition. D1 adds S, and D2 makes `satp`.MODE writable, so FIOM (bit 0 of each register) is writable. On this single in-order hart a writable FIOM changes no observable order. Norms `menvcfg_fiom_fence_op` and `senvcfg_fiom` still apply. The other fields are read-only zero because the extension that defines each one is absent. That is the permission in norms `menvcfg_cbie_rdonly0`, `menvcfg_cbcfe_rdonly0`, `menvcfg_cbze_rdonly0`, `menvcfg_pbmte_rdonly0`, `menvcfg_adue_rdonly0`, `menvcfg_stce_rdonly0`, `menvcfg_cde_rdonly0`, `menvcfg_pmm_rdonly0`, and `menvcfg_dte_sdt_rdonly0`, and the matching `senvcfg` norms `senvcfg_cbie_rdonly0`, `senvcfg_cbcfe_rdonly0`, `senvcfg_cbze_rdonly0`, and `senvcfg_pmm_ssnpm`. Zicfilp and Zicfiss are absent, so LPE and SSE are read-only zero as well. `menvcfgh` does not exist at XLEN 64 (norm `menvcfgh_sz_acc_op`).

The H-extension `vs*` CSRs (`src/csr/mod.rs:174-182`) are not part of this profile. The hypervisor chapter defines those VS CSRs, and the CSR chapter lists them as hypervisor registers. Norm `misa_H_op` enables the H extension through `misa` bit 7, which stays 0. A hart that does not implement H does not have those addresses, and norm `Zicsr_nonexistent_rsv` reserves access to a non-existent CSR address. The hypervisor remains a non-goal. `misa` bit 7 stays 0 because the `misa` row below rejects a write that sets it, not only because reset leaves it clear.

**M3. MPRV.** DECIDED. MPRV is in scope, and D9 carries it. No separate behavior is defined here.

**M4. Translation cache on the public path.** DECIDED. v1 does not cache translations on the public path. Every translated access walks the page table. SFENCE.VMA is still decoded and executed, and with nothing cached it is an ordering no-op. This drops the roadmap Stage 4 deliverable named "TLB integration" for v1, and that deliverable is recorded as deferred, not delivered. The component TLB stays available to its own tests, and the two defects in §2, the missing D update on a hit and the dropped superpage VPN bits, are fixed so those tests no longer record the wrong result.

**A/D observation.** DECIDED with D4. A successful A/D write is a visible memory effect. On a retired instruction it is a `MemoryEffect` in `CommitRecord.effects.memory`, ordered before the explicit access, with `MemoryEffect.implicit` set. On a faulting instruction it is a `MemoryEffect` in `TrapRecord.effects.memory`, and that instruction has no `CommitRecord`. A faulting instruction never has a `CommitRecord` (`Observation::build`, `src/core/observation.rs:131-195`), so the earlier wording that only excluded the effect from one did not say where it goes. `implicit` is the field D4 adds. It is not a second observation record.

## 9. Risks and activation boundary

The risks that follow from the decisions:

- A walk read that loses the target, host, protocol, and unknown distinction would turn a `SimulatorFailure` into a guest fault. D3 makes the three outcomes separate acceptance checks.
- Reusing the component walker without the §2 fixes would accept a reserved PTE, translate a misaligned superpage, and report every failed walk read as one flattened access fault. Those fixes are in scope.
- The deferred Stage 3 comparison, CI publication, and noise calibration have no owner after the D0 waiver. Stage 5 and later inherit the waiver unless a later milestone picks the work up. This contract does not.
- A `satp` write implemented as a trap would break the WARL rule in D2. The acceptance check writes an unsupported MODE and expects the old value.
- Translating after `hart_issued_paddr` (`src/core/mod.rs:463`) would make a PTE PPN a storage offset. D7 puts translation first, and the mapped fixture uses guest physical PPNs.
- U-mode WFI is a profile choice, not a missed requirement. Norm `mstatus_tw_umode_op` allows the instruction to complete inside an implementation-specific bounded time, and a completed WFI may be a NOP (norm `wfi_resume_reason`). D10 does not take that allowance. It raises illegal-instruction immediately in U-mode, at TW = 0 and at TW = 1, and the §4 fixture checks both values. Reporting U-mode WFI as an unsupported legal instruction, which is what `src/core/mod.rs:1543-1544` does today, is the behavior this milestone replaces.
- Bare-guest behavior can drift. The bare fixture and the A6 through A10 suites are the guard, except the tests D7 names. That exception is the FP tests, the M-mode WFI test, and the FENCE.I tests. The CSR tests named in D7 are expected to change and are not part of that guard.
- WFI is not a waiting instruction in this milestone. D10 retires it in M-mode, and in S-mode when TW = 0, as the NOP the WFI rule permits. A WFI that stalls the hart stays with Stage 5.
- FLW, FSW, FLD, and FSD retire on the public path today and move raw bits. Stage 4 makes every such encoding raise illegal-instruction. A guest that used those instructions as raw moves no longer runs. D7 records the break. No project guest and no A10 fixture is assembled with F or D.

A later milestone implements IEEE-754 RV64F and RV64D. That milestone is a new feature. The Stage 4 hart does not implement F or D, `misa` reports neither, and nothing in this contract leaves an F or D rule unimplemented. The later milestone has this shape.

- The arithmetic backend is a soft-float implementation, Berkeley SoftFloat 3e or a pure-Rust equivalent. Host `f32` and `f64` do not honor per-instruction rounding or exact exception flags.
- The decoder gains the four fused-multiply-add opcodes. Dispatch uses `funct5` = funct7 bits 6:2, `fmt` = funct7 bits 1:0, `rm` from funct3, and the `rs2` subfield. Reserved `rm` values 5 and 6, and dynamic `rm` with an invalid `frm`, raise illegal-instruction.
- The operations cover NaN boxing on read and write, the canonical NaN, FMIN and FMAX number rules, quiet FEQ against signalling FLT and FLE, saturating FCVT with the invalid flag, FCLASS, raw FMV, fused FMA, and exact `fflags`.
- `misa` F and D become 1. FS becomes writable and gates the floating-point instructions and `fflags`, `frm`, and `fcsr`, and a write of that state sets FS to Dirty.
- Guests for that milestone are built with `-march=rv64imafd_zicsr`.
- Acceptance is riscv-arch-test F and D, riscv-tests rv64uf and rv64ud, TestFloat vectors for each operation and rounding mode with bit-exact flags, and Spike lock-step on random floating-point programs.
- That milestone replaces or retires `src/isa/rv64f`, `src/isa/rv64d`, and the `f_*` and `d_*` component tests. Until then those tests stay labeled as component tests that do not implement IEEE 754 and are not on the public path.

Activation boundary. This document becomes the Current contract only through the rolling workflow. It is not activated by the decisions recorded here. A separate approval has to accept this revised contract, and a separate documentation-only rotation then archives A10 and replaces `docs/dev-plan.md`. A10's own closeout still has a pending independent review, and that review is an A10 item. This document authorizes no implementation and no archive.
