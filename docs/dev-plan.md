## 1. Objective and inherited profile

Let the single Hart of the TLM route run ahead of committed Platform time by a bounded local offset, syncing at a selected quantum and at a fixed list of forced points, under one delay-accumulation path. With the quantum off, a run is exactly today's run. With it on, time-derived timer recognition may be late by a declared bound, every other observable keeps its parity value, and committed time never drifts.

The inherited profile is everything delivered through the completed direct-memory contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the `capi` C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim: every turn still samples the interrupt lines, and the proof that a quantum defers Platform synchronization is sync counts, not timing.

Vocabulary used throughout, in Platform ticks:

- `Q` is the selected quantum. `C` is committed time, the CLINT `mtime`. `O` is the local offset. `L` is the Hart's local time, `C + O` with wrapping addition.
- A *sync* sets `C` to `L` and `O` to zero, then republishes `time` and the interrupt lines.
- `t` is `turn_completion_bound_ticks()` of the selected route: a turn advances time by at most `1 + t`.
- A *parity run* is the same run with `Q` = 0.
- A *time-derived crossing* is MTIP rising only because `mtime` reached `mtimecmp`, with no store to the CLINT in that turn.

## 2. Selected decisions

References are unchanged from the archived direct-memory contract: ISA Manual 20250508, Debug Specification 1.0 at `5695c0aaa7a3c228e14702e1268eb5a5e50e3cb8`, IEEE 1666-2023 (SystemC, including TLM-2.0), and Accellera SystemC 3.0.2 at commit `70b0fc8e4a74acc677b0fc73cea08f940c2115d5`. The OpenOCD, Spike and riscv-arch-test pins are unchanged, and the dev image is unchanged.

Every decision below was approved on 2026-11-06 under the delegation recorded above. Existing source, header, script and integration comments that cite `dev-plan` D numbers refer to the archived blocking-transport contract, and those citing `direct-memory D<n>` refer to the archived direct-memory contract; new code cites `quantum D<n>` for this contract and `quantum F<n>` for a §3 forced sync.

| Decision | Accepted selection |
| --- | --- |
| D1. Delivery | One bounded timing cut of roadmap Stage 7: temporal decoupling for one Hart on the blocking TLM route, in Rust first, then the CLI and guest suite, then the C ABI, then the SystemC smoke. The native and flat routes are unchanged. |
| D2. Selection | `MachineConfig` gains a public `quantum: u64` field in Platform ticks. `MachineConfig::new` selects 0, which is off, and this breaks struct-literal construction. A non-zero `quantum` with `Transport::Native` is the existing `MachineError::UnsupportedTransport`, whose message is widened to name this case; a flat Platform already refuses a TLM route. A `quantum` for which `(Q + t + 1) × tick_period` overflows `u64` femtoseconds is refused at build with `MachineError::Placement`, the existing channel for an invalid maximum delay. `run --quantum <ticks>` exposes it and requires `--transport tlm`; the option without it, whatever its value, is a CLI error with status 2. It composes with `--dmi` and `--rbb-port`. `load_and_run_file_with_config` honors the field; the `RiscVSimulator` and the other `load_and_run*` facades keep the native route. The CHANGELOG names every public addition. No other public signature changes. |
| D3. Clock model | `O` lives in `SystemBus` beside the CLINT, under the bus lock, so a device access can flush it and a fresh Platform cannot inherit it. Each turn start presents `L` through `csr.set_time` and still samples `machine_interrupt_lines()`, so `rdtime` needs no sync and MSIP, MEIP and SEIP keep their per-turn sample. The lines derive from `C`, so only MTIP can be stale, and only by a time-derived crossing. `Platform::read_mtime` keeps returning `C`; a separate accessor returns `L`. A sync performs no target call, charges no delay, changes no counter and cannot fail. With `O` zero it is a no-op and is not counted. |
| D4. One accumulation path | The existing `Installed::turn` computation stays the only input: `advance = delay.ticks + u64::from(completed_turn)`, with `delay` taken once from `take_transport_turn_delay`. A `b_transport` response and a direct-memory latency already share `account_delay`, so each transaction is converted once, under the adapter's existing per-access rounding, and a sync never reconverts. With `Q` non-zero, `advance` is added to `O` in place of `advance_mtime` or `advance_mtime_by`. The two overflow rules apply to `L` at the same point: a turn with no delay ticks wraps, a turn with delay ticks is checked, and a failed check is today's simulator failure, retaining the completed facts. Debug work still goes through `discard_transport_turn_delay` and never reaches `O`. A failed turn's known delay enters `O` once and F6 syncs it. `transport_delay_femtoseconds`, `mcycle` and `minstret` are the same as the parity run for the same turns. |
| D5. Threshold sync | At the end of every turn, `O >= Q` syncs. `O < Q` therefore holds at every boundary that did not sync, and no turn starts with `O >= Q`. `Q` = 0 means no local offset exists and each turn advances `C` directly, on exactly today's path. `Q` = 1 syncs at every boundary through the sync path. |
| D6. Forced syncs | Exactly the §3 list. A forced sync adds no turn, tick or delay. An added point can only shorten lateness, so the list may grow only by contract amendment, and an omitted point is a defect. |
| D7. Parity | `Q` = 0 is the identity: byte-identical commit logs and CLI stdout, and the same `mtime`, events, `BoundaryFacts` values, grant partition and C ABI facts as this contract's base commit. `Q` = 1 gives the same commit logs, `mtime` at each boundary, events and exit as `Q` = 0, and is precise under ADR-0004 §6.3; only the D10 report and the D12 grant partition differ. For `Q` >= 2, a run with no time-derived crossing has the same commit log, `mtime` at each sync, events and exit as its parity run. |
| D8. Interrupt bound | For `Q` <= 1 lateness is zero. For `Q` >= 2 and a time-derived crossing, let `P` be the `L` of the turn start at which the parity run presents MTIP and `R` the same for the quantum run, over their common prefix. Then `0 <= R - P <= Q - 1 + t`, and the same number bounds the lateness in completed turns because each advances at least one tick. With a zero-delay target that is at most `Q - 1`, so strictly less than one quantum. The bound covers the `mip` and `sip` a guest reads, trap acceptance and an MRET or `mie` write that unmasks an overdue interrupt. Lateness is zero for MSIP, MEIP and SEIP (per-turn sample), for any MTIP change caused by a CLINT store (F1), and for a wake from WFI (F3). MTIP is never early: F1 covers `mtimecmp` and `mtime` stores, and F10 covers a `u64` wrap of `L`. Deadline overshoot is zero: `run_grant_inner` tests `L`, and `reached_virtual_deadline`, `wake_turn_fits` and `settle_wait` run on the Waiting path where F3 has made `O` zero. |
| D9. No drift | After every sync, `C` equals its initial value plus that run's completed turns, charged delay ticks and idle-jump distance, with any guest `mtime` store rebasing it exactly as in a parity run. A device access sees `C = L` as of the start of its turn, the value the parity run shows it. Until the first differing recognition, `C` at a sync equals the parity run's `mtime` at the same turn. A late interrupt shifts the later instruction sequence but loses or gains no tick; `Q` >= 2 runs are compared by this conservation identity after that point, not by turn-indexed equality with the parity run. |
| D10. Reduced-accuracy report | Selecting `Q` >= 2 is the explicit ADR-0004 §6.3 request. `BoundaryFacts` and `ExecutionResult` gain `quantum: Option<QuantumFacts>`, `None` when off, with `ticks`, `interrupt_latency_bound_ticks` (0 for `Q` = 1, otherwise `Q - 1 + t`), `reduced_accuracy` (`Q >= 2`) and `syncs`. Deadline overshoot is declared as zero by D8 and needs no field. `print_result` adds one `Quantum:` line only when the fact is present, so `Q` = 0 stdout stays byte-identical. `syncs` counts syncs that moved `C`, and a non-empty RAM-only stretch at `Q` >= 2 gives `syncs` below completed turns. |
| D11. Transaction offset | `BlockingTransaction` gains a read-only `local_offset() -> Femtoseconds` request accessor: the current `O` plus this turn's already-charged ticks, multiplied by the tick period, for Hart transactions. It is zero with `Q` = 0, for `DebugInbound`, and always for debug transport. It is timing metadata only: address, bytes, status and permissions never depend on it. `set_response_delay` keeps its meaning, the delay the target adds, so the adapter's declared-maximum check and D4 are unchanged and the offset is never charged. A direct access has no transaction and reads no offset. `BlockingTarget` is unchanged, and `ZeroDelayRam` ignores the value. |
| D12. C ABI | Additive under the header's append-only rule, so `ruscv_machine_create` keeps its signature. `ruscv_target` gains a final `uint64_t quantum_ticks`; zero is off, a NULL target selects the native route and so cannot select a quantum, the table is copied at create and the value persists across `ruscv_machine_reset`. A value D2 refuses is `RUSCV_ERROR_CONFIG`. `ruscv_payload` gains a final `uint64_t local_offset_fs` request field carrying D11. `ruscv_boundary` gains final `quantum_ticks`, `interrupt_latency_bound_ticks`, `quantum_syncs` and `int32_t quantum_reached`. With `Q` non-zero, every sync ends the grant at that boundary, so kernel lag and `O` are one value, and every grant return syncs first, so `committed_end_fs` and `consumed_fs` are post-sync and `wait(consumed)` stays exact. `quantum_reached` reports a D5 sync; a forced sync ends the grant without it. The grant's horizon, `deadline_blocked` and `residual_slack_fs` tests use `L`. Clipping the horizon to `Q` is not used, because `bound_ticks` of 2 would then block every grant at `Q` = 1. With `Q` = 0 grants are unchanged. |
| D13. SystemC | `integration/systemc` gains `--quantum <ticks>`, placed in the target table. `serve` passes `delay = sc_time::from_value(payload.local_offset_fs)` into `b_transport` and returns `payload.delay_fs = (delay - offset).value()`. A returned `delay` below the offset cannot be represented as an added delay, so the initiator marks the transaction `TLM_INCOMPLETE_RESPONSE`, which the adapter maps to a protocol failure. `RamTarget::b_transport` stops assigning `SC_ZERO_TIME` to `delay` and leaves it unchanged, adding nothing, as its zero declared maximum requires. Callbacks still must not `wait`, advance time or re-enter the ABI. The grant loop is the only quantum keeper: there is one initiator, so `tlm_quantumkeeper` and `tlm_global_quantum` are not used. |
| D14. CI and documentation | The guest suite and the SystemC smoke add quantum passes; no new CI job and no dev-image change. `cargo build`/`test --all-features` still need no C++ toolchain. `docs/integration/systemc-tlm.md` becomes normative for the offset, grant, sync and bound rules on this host and its open items keep only non-blocking transport. The README, CLI help, CHANGELOG and verification docs state `--quantum`, the `MachineConfig` and report additions and the C ABI additions. |

## 3. Forced syncs and ownership

The Machine owns the `quantum` selection as composition configuration, and the Platform owns `O` with the rest of Platform time, as amended in ADR-0003. The Hart is unchanged: it reads `time` and the lines exactly as it does now and never sees a quantum. In the SystemC host the external kernel still owns global time and commits only a grant's consumed amount.

A turn-end sync below runs after that turn's `advance` has entered `O`, before the boundary returns, on the path `Installed::turn` already uses to publish time.

| Point | Trigger, from current code | Behavior |
| --- | --- | --- |
| F1. Device access | A Hart request or atomic envelope routed to a CLINT, PLIC, gateway, UART or HTIF window, including one the device rejects, through `SystemBus::native_transact_from`, `SystemBus::native_transact_atomic` or the `MemoryInterface` implementation for `SystemBus`. An unmapped address is not a device. | Under the same bus lock, before the device sees the access, flush `O` to `C`. The current turn's delay stays pending, so the device sees the parity `mtime`. The turn then ends with a sync, so a store's effect on the lines reaches the next turn as in a parity run. |
| F2. HTIF and `tohost` | A `PlatformEvent` queued by the turn, which F1 already covers, and a non-zero RAM-resident `tohost` value read by `OwnedMachine::observe_tohost` or the `Machine::step` sample. A zero poll is not a sync. | Sync before the sample or event reaches the Runner or `observe_exit`. Debug transport polling is unchanged. |
| F3. WFI | Turn end with `is_wfi_waiting()`, and any `StepOutcome::Waiting`. | Sync, so the wake check, `settle_wait` and the idle jump see `C = L`. Wake timing equals the parity run. |
| F4. Debug | `StepOutcome::DebugHalted` of either form at turn end. Before any work in `apply_dmi`, `advance_debug_command` and `service_pending_sba`, including `sample_debug_inputs` and `reload_for_ndmreset`. An idle `debug_boundary` with no work is not a sync. | Sync, so a debugger and SBA see parity time. Debug work then adds nothing to `O` (D4). |
| F5. Single step | `single_step` true on any turn, which covers `Machine::step` and `OwnedMachine::step`. | Turn-end sync. Every shared `Machine` control, including `inspect`, `set_hart_state`, `settle_wait` and `receive_uart`, therefore runs at `O` = 0 and needs no point of its own. |
| F6. Failure and unknown completion | `StepOutcome::SimulatorFailure` of any kind, including an unknown completion, an overshoot and the D4 clock failure. | Turn-end sync of `O`, including known delay. The sync makes no target call, so a poisoned transport is not touched. The `uncertain` and lifecycle facts are unchanged. |
| F7. Run stop | `last_slot` on a turn, every Runner return from `run_native_inner`, and every return of `run_grant_inner`, including a budget, horizon, `deadline_blocked` or waiting return. | Sync before facts are reported, so the `--max-cycles` boundary and the final result carry `C = L`. |
| F8. Quiesce and drain | `request_quiesce` reaching a boundary, `OwnedMachine::quiesce` and `acknowledge_drain`. | Sync before the acknowledgment. |
| F9. Reset | `fresh_reset`, `reload_for_ndmreset` and `ruscv_machine_reset`, including the unknown-completion path that builds a fresh `OwnedMachine`. | The old generation is already at `O` = 0 by F4, F6, F7 or F8. The fresh Platform starts with `C` = 0 and `O` = 0. No offset crosses a generation. |
| F10. `u64` wrap | A zero-delay turn leaving `L < C`, which only a guest-written `mtime` near `u64::MAX` can produce. | Turn-end sync, so the wrapped value presents as it does in a parity run and MTIP is never stale high. |

Not sync points: RAM accesses, including atomics and direct-memory copies; reads of `time`, `mip` or `sip`; trap entry; MRET and SRET; writes to `mie`, `mstatus` or `sie`; FENCE, FENCE.I and SFENCE.VMA; a direct-memory invalidation, under the 2026-11-05 ADR-0004 amendment; commit-log observation, which carries no time; and a zero `tohost` poll. D8 covers their effect on recognition. No public caller other than D11's request field and the D10 report can observe `O` non-zero, because every public stopping point above is a sync.

## 4. Sequenced units and acceptance

These are requirements for subsequent implementation. Activating this contract does not implement them.

| Unit | Required observable proof |
| --- | --- |
| U1. Local time and threshold | Per D2–D5 and D10: `MachineConfig.quantum`, build validation, `O`, `L`, the accumulation path, threshold and overflow rules, F3, F5, F6, F10 and the `quantum` facts. The field stays `pub(crate)` until U2 completes, so no public caller can select a partially synchronized quantum. Rust tests with a non-zero-delay test target prove `Q` = 0 and `Q` = 1 equal the base route turn by turn in `mtime`, `time`, counters and delay total, `O < Q` at every unsynced boundary, one transport delay charged exactly once with direct memory on and off, `mcycle` and `minstret` unchanged by a sync, the overflow split at `u64::MAX`, and native and oversized selections refused. |
| U2. Forced syncs and the bound | Per D3, D6, D8 and D9: F1, F2, F4, F7, F8 and F9, with the field made `pub`. One focused test per point proves its behavior at `Q` >= 2, including a CLINT `mtime` read in the middle of a quantum returning the parity value, a store to `mtimecmp` reaching the next turn exactly, an SBA read of `mtime` under a halted Hart, an unknown completion at non-zero `O`, and a reset leaving no offset. A new guest, `quantum_timer_spin`, arms `mtimecmp` through the CLINT and spins with MTIE set, so MTIP is a time-derived crossing: at `Q` = 1 its commit log equals native, at a selected `Q` >= 2 its recognition is late by exactly the computed value, non-zero and within D8, and its final `mtime` satisfies D9. |
| U3. CLI and guest parity | Per D2, D7, D10 and D14: `run --quantum`, the status-2 refusal, the `Quantum:` line and help text. `scripts/run_elf_tests.sh` runs every guest with `--transport tlm --quantum 1` and with `--transport tlm --quantum 1024` under its declared profile. The parity set's commit logs are byte-identical to native on both passes; its seven guests have no time-derived crossing, since `s5_timer` raises MTIP by a store to `mtimecmp`. Every other guest keeps its exit code, and any guest that needs a time-derived exception is listed by name with its reason. One test runs `--transport tlm --dmi --quantum 1024` on a parity guest and shows `syncs` below completed turns. One live debug-attach session under `--transport tlm --quantum 1024` halts, reads `mtime` by sysbus access and resumes. Native results and A10 unchanged. |
| U4. C ABI | Per D11 and D12: header, `capi` additions and the plain-C smoke cover off, `Q` = 1, `Q` >= 2, `quantum_reached`, a forced sync ending a grant, `local_offset_fs` matching a recorded expected sequence for a RAM-only stretch and zero when off, `committed_end_fs` advancing by exactly `consumed_fs`, reset, and an unknown completion at non-zero `O`, after which reset restores the configured quantum. A NULL target with no quantum stays native. `--all-features` still needs no C++ toolchain. |
| U5. SystemC smoke | Per D13: `RamTarget`, the initiator and `main.cpp` gain the option. `scripts/test_systemc_smoke.sh` runs both smoke guests with `--quantum 1` and `--quantum 1024`, with and without `--dmi`, and with native commit-log comparison. It requires the kernel clock to equal `committed_end_fs` after every grant and a grant count at `--quantum 1024` strictly below the same guest's `--quantum 1` pass. The grant limit the smoke sets is raised as needed, and that is the only existing bound that changes. A test target proves a decreased `delay` is a protocol failure and an added delay is charged once. The existing passes and the early-`sc_stop` control are unchanged. |
| U6. Exit | Per D14, the documentation is complete and accurate. Every §4 negative control is registered. CI runs the full Rust quality gate, the guest suite with all TLM passes, the C ABI smoke, the SystemC smoke, the tool script and the mutation runner. Obtain an independent review of the final committed PR head. The A10 oracle and certification deferral remain unchanged. |

Dependencies: U1 first. U2 requires U1. U3 and U4 require U2 and may proceed in parallel. U5 requires U4. U6 requires all.

Required negative controls, under the existing mutation-runner pattern (`scripts/debug/stage6-mutations/cases.json`, `scripts/verify_stage6_mutations.py`), with unit names prefixed `quantum-u<n>-`:

- `MachineConfig::new` selecting a non-zero quantum, or `Q` = 0 taking any path that changes `mtime`, events or a commit log;
- a non-zero quantum accepted on `Transport::Native`, or `--quantum` accepted without `--transport tlm`;
- the threshold ignored, or tested so that a turn starts with `O >= Q`;
- a sync skipped at each of F1 to F10, one control per point, including a device reading `mtime` before the flush and a grant return that leaves `O` non-zero;
- a transport delay or direct-memory latency added twice, or dropped, between `advance` and `O`;
- `O` or a sync charged into `mcycle`, `minstret` or `transport_delay_femtoseconds`;
- debug work adding to `O`;
- a sync that loses or gains ticks, so `mtime` drifts from the D9 identity;
- CSR `time` presented from `C` instead of `L`;
- the overflow split replaced by one rule, so a parity run near `u64::MAX` diverges;
- an interrupt recognized later than the D8 bound, or MTIP derived from `L` so that the bound test's expected lateness changes;
- `O` surviving reset;
- `reduced_accuracy` or `interrupt_latency_bound_ticks` misreported, or the `Quantum:` line printed when off;
- `local_offset` non-zero when off, or included in the charged delay;
- `committed_end_fs` read before the grant-return sync;
- a grant continuing past a sync with `Q` non-zero;
- the SystemC initiator returning `delay` without subtracting the offset, or accepting a decreased `delay`.

Keep their small patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No `nb_transport`, TLM phases beyond blocking, TLM-modeled CLINT/PLIC/UART/HTIF, SystemC-modeled interrupt lines, multi-Hart or DMA, per-Hart or per-target quantum, a quantum that changes during a run, next-event clipping of the quantum, adaptive quantum, rollback, `tlm_quantumkeeper` or `tlm_global_quantum`, a sync triggered by a guest read of `time` or `mip`, block execution or translated code, removal of the per-turn line sample, direct memory for any device, multiple RAM targets, inbound masters other than the existing DM, hardware triggers, non-Linux FFI targets, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile.

Non-blocking transport requires a separately approved timing contract. Stage 8 remains conditional.

## 6. Activation boundary

This documentation-only rotation archives the direct-memory contract, applies the bounded 2026-11-06 quantum amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle.
