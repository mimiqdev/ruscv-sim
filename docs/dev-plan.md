## 1. Objective and inherited profile

Let an external host serve the HTIF endpoint through the same window-indexed device table that already serves the UART window: one guest dword access to `0x4000_8000` becomes one blocking device transaction, answered either by the in-tree Rust endpoint or by a target the SystemC host supplies through the C ABI, with the same window policy, the same publication sink, the same run stop and the same exit classification as today. A host-served endpoint owns the window's dword answers and nothing else: Platform time, the interrupt lines, routing, run control and the exit vocabulary stay where they are. With no host HTIF target, a run is exactly the devices contract's run on either route.

The endpoint is the devices contract's second device window. Its policy is Platform code: the exact start `0x4000_8000`, one complete eight-byte dword, no fetch, and a read-modify-write envelope that stays Platform-side (`src/executor.rs:1087-1114`, `:1252-1300`). On the TLM route the plain dword read and write go to `DevicePath::htif()` (`src/executor.rs:1116-1126`), whose target is always `InTreeHtif` today (`src/machine/platform.rs:216-222`): a read fills the response bytes with zero, an accepted write reports one `HtifWrite(value)` event, and `finish_device` publishes it through `publish_htif_write` (`src/blocking/in_tree.rs:82-118`, `src/executor.rs:632-640`, `:619-624`). The one sink is installed by `Platform::build`: it pushes `PlatformEvent::HtifWrite(value)` and then calls `config.htif_write(value)` (`src/machine/platform.rs:248-258`). The run stop reads that event: the public loop and the debug boundary decode it with `try_extract_exit_code` (`src/executor.rs:1641-1670`, `:2535-2542`, `:2015-2030`), and the C ABI's `observe_exit` checks the same events before the RAM `tohost` sample (`src/capi/host.rs:780-790`). The typed `MemoryInterface` host view answers zero on a dword read (`src/executor.rs:1319-1323`) and publishes one value on a dword write without reaching a target (`:1394-1405`). The C ABI names one device window, `RUSCV_DEVICE_UART` 0 (`include/ruscv_sim.h:157-158`), and `c_device_window` maps only that code (`src/capi/mod.rs:573-581`); the device-event tag for an HTIF write already exists (`include/ruscv_sim.h:162-164`) and the event's value is the response's write data (`src/capi/target.rs:658-676`). `DeviceTargets` carries only a UART slot (`src/blocking/device.rs:136-173`), and `DevicePath` can select a host target only for that window (`:418-460`). The SystemC host offers `--uart-target` and three UART fault options, and no HTIF option (`integration/systemc/main.cpp`, `scripts/test_systemc_smoke.sh:1136-1368`). No project-authored guest writes the endpoint: `hello` and `atomic_tohost_exit` exit through a RAM-resident `.tohost` word (`tests/bare-metal-riscv-test/rv64i/hello.S`, `rv64a/atomic_tohost_exit.S`), so a host HTIF pass needs its own fixture.

The inherited profile is everything delivered through the completed devices contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the quantum, the non-blocking AT path with its retirement rules, the two device windows with in-tree targets, the host-served UART window through the C ABI, the two publication sinks, reset at install, the device fault options, the append-only C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim.

Vocabulary used throughout:

- The *HTIF window* is the endpoint `0x4000_8000` with eight bytes; the *in-tree target* is `InTreeHtif` and the *host target* is a `BlockingDeviceTarget` the C ABI supplies for that window.
- A *tohost write* is a guest dword store that starts at the window base; a *tohost read* is the matching load.
- An *HTIF event* is the at-most-one `PlatformEvent::HtifWrite(value)` an accepted tohost write reports. There is no other HTIF event, and no fromhost event.
- The *published value* is the eight bytes that reach the sink, which are the response's write bytes.
- The *run stop* is the existing `PlatformExit` classification a published value produces when it decodes as an exit.
- A *parity run* is the same guest with the same options and `--htif-target in-tree`, or the native route when the comparison is architectural.

## 3. Ownership, ordering and events

The Platform keeps the window map, the pre-target policy, routing, the event queue, the single sink and the presented lines; a device target owns one window's register state. The Machine owns admission, lifecycle, reset and the selection. The Hart is unchanged and never sees a target, a transaction or an event. The Runner or external kernel owns the exit classification, and the C ABI carries one table per window.

| Window | Base and size | Devices contract | This contract |
| --- | --- | --- | --- |
| UART | `0x1000_0000`, `0x100` | In-tree target by default; host target through the C ABI; one sink | Unchanged |
| HTIF | `0x4000_8000`, 8 | In-tree target: dword read zero, dword write one `HtifWrite`; atomic envelope Platform-side | In-tree target by default; host target through the C ABI answering the same two requests and reporting the same event; the envelope stays Platform-side |
| CLINT | `0x0200_0000`, `0xC000` | `SystemBus` state; `mtime`, `mtimecmp`, MSIP | Unchanged on both routes; not a device target |
| PLIC | `0x0C00_0000`, `0x40_0000` | `SystemBus` state; priority, pending, enable, threshold, claim/complete | Unchanged on both routes; not a device target |
| Source-1 gateway | `0x4000_0000`, 4 | `SystemBus` level word and its pending reconciliation | Unchanged on both routes; not a device target |

An event beside a non-`Ok` status, a second event, a wrong-window tag, an event on a `Read` command (D10), an `HtifWrite` value that is not the request's eight data bytes on the HTIF window (D10), or a changed address, command or length is a protocol failure of that access; an unknown completion keeps its precedence and publishes nothing.

Per-rule controls run under the mutation runner (`scripts/debug/stage6-mutations/cases.json`, `scripts/verify_stage6_mutations.py`). Each patch makes the change named at its patch site and touches one file, and the test behind the row's observable must fail. The run stop and the exit decode are the devices contract's sites rather than new ones, so this contract adds no control for them; the existing `capi` and facade tests fail if that decode changes.

| Control | Patch site | Observable that must fail | Owner |
| --- | --- | --- | --- |
| `htif-u1-route` | Host HTIF selection in `DevicePath` | A host HTIF target's transaction count is non-zero for a guest that reads and writes the endpoint | U1 |
| `htif-u1-reset` | HTIF target's `transport_reset` call in `Platform::build` | A host HTIF target receives exactly one transport reset per install, and its state does not survive a reinstall | U1 |
| `htif-u1-read-event` | Command check in `validate_response` | A UART or HTIF host target that reports its window's event on a read is a protocol failure, and nothing is published | U1 |
| `htif-u1-value` | HTIF value comparison in `validate_response` | A host HTIF target that reports an `HtifWrite` value other than the request's eight data bytes is a protocol failure, and nothing is published | U1 |
| `htif-u2-window` | `c_device_window`'s `RUSCV_DEVICE_HTIF` arm | Attach with `RUSCV_DEVICE_HTIF` returns `RUSCV_OK` and the attached target serves the endpoint | U2 |

SystemC fault-option controls are not mutation-runner cases, because that runner runs only `cargo test --offline --all-features` and D9 keeps `--all-features` free of a C++ toolchain. U3 owns them as options of the smoke binary in the style of `--fault-uart-no-lsr`. `scripts/test_systemc_smoke.sh` runs each with its own failure assertion, and a run that passes with one set is a smoke failure:

- `--fault-htif-drop-event`: `HtifTarget` answers the exit write with `RUSCV_TLM_OK` but no `HTIF_WRITE` event. The run must not stop as an exit; it must exhaust its turn bound and fail with the turn-limit diagnostic, and no value may reach the sink for that write.
- `--fault-htif-wait`: `HtifTarget::b_transport` waits one tick. The run must fail with a diagnostic naming host elapsed time on a device transaction, and no value may reach the sink.
- `--fault-htif-event-on-fault`: `HtifTarget` reports the exit write with `RUSCV_TLM_ADDRESS_ERROR` and one `HTIF_WRITE` event. The run must fail as a protocol failure of that access, and no value may reach the sink.

Keep the mutation patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No fromhost register or host-to-guest input entry, no HTIF console decoding in the crate, no change to the endpoint's window policy or atomic envelope, no host stop or run-control entry, no host-chosen exit code, no change to the RAM `tohost` sample or clear path, no device delay or host-time annotation, no device direct memory, no device atomic envelope, no non-blocking device transport or device phases, no more than one outstanding transaction, no device target for CLINT, PLIC or the source-1 gateway, no SystemC-modeled interrupt line or interrupt controller, no UART inspection snapshot for a host-served window, no DMA, multi-Hart, arbitration or coherence, no second RAM target, no inbound master other than the existing DM, no `tlm::` `TlmBus` routing on the public path, no change to the native route's answers, no checkpoint or restore, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile. Issue #207 stays open outside this contract.

Retained direction, each needing its own approved contract: device delay and host-time annotation with the turn bound and grant horizon extended to match; CLINT or PLIC targets only if time and line authority move under an accepted ADR amendment; SystemC-modeled interrupt lines; a UART inspection snapshot for a host-served window; and HTIF fromhost, console input and syscall proxying through a host-served endpoint.

## 6. Activation boundary

This documentation-only rotation archives the devices contract, applies the bounded 2026-11-08 host-HTIF amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle. Later implementation must meet the units above on its own reviewed commits.
