## 1. Objective and inherited profile

Make a platform device a blocking TLM target on the TLM route: one device register access becomes one `b_transport` transaction carrying the existing physical category and initiator, answered either by the in-tree Rust device or by a target the SystemC host supplies through the C ABI, with the same status mapping, the same guest-visible side effects and the same Platform events as today. A host-served device owns one window's register state and nothing else: Platform time, the interrupt lines, routing and run control stay where they are. With no host target, a run is exactly today's run on either route.

Today only the guest-RAM slot is a transport target. `--transport tlm` builds `Transport::tlm(Arc::new(ZeroDelayRam::new()))` (`src/main.rs:250`) and `MachineConfig.transport` carries that one target (`src/machine/mod.rs:154`); `RamSlot` is either the native `SimpleMemory` or that blocking target (`src/ram.rs:89`). Device registers never reach it: `SystemBus::native_transact_from` matches RAM first by `contains_range` and then runs the CLINT, PLIC, gateway, UART and HTIF branches (`src/executor.rs:858-1060`), and each of those branches is Rust state on the bus, on the native and the TLM route alike. The UART window is `0x1000_0000` with `0x100` bytes (`src/executor.rs:185-188`) over a `Uart16550` whose own `UART_SIZE` is 8 (`src/peripherals/uart16550.rs:38`); a raw access is byte-only, rejects fetches and rejects every atomic width (`src/executor.rs:929-981`, `:1122-1134`). HTIF is an exact eight-byte endpoint at `0x4000_8000` (`src/executor.rs:189-192`) whose dword write fires `htif_write_callback` with the written value and whose dword read returns zero (`src/executor.rs:983-1046`, `:1204-1214`). The UART publishes a transmitted byte from `write_thr`, before the FIFO check (`src/peripherals/uart16550.rs:399-410`), through the callback `Platform::build` installs to push `PlatformEvent::UartTransmit` and call `config.uart_output` (`src/machine/platform.rs:172-190`). CLINT and PLIC are read by the Platform itself for `mtime`, `mtimecmp` and the four lines (`src/executor.rs:362-381`), and the PLIC source-1 level, its pending reconciliation and claim/complete are bus state (`src/executor.rs:627-643`, `:726-828`). Each `Installed::build` constructs a fresh `Platform` (`src/machine/mod.rs:522`), so device state is reset by construction today, while the RAM slot's `begin_window` asks its target for a transport reset and zero-fills the window (`src/ram.rs:215`). The blocking adapter queries direct memory once, after an `Ok` Hart-initiated non-atomic transaction that set `dmi_allowed` (`src/blocking/adapter.rs:734-752`), and only RAM can reach it. `src/tlm`'s `TlmBus` and the peripherals' `TlmTarget` implementations are component code with component tests (`tests/tlm_tests.rs`, `tests/peripheral_tests.rs`); they are not this route, and `src/blocking` is deliberately separate from `src/tlm` (`src/blocking/mod.rs:3`).

The inherited profile is everything delivered through the completed non-blocking contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the quantum, the non-blocking AT path with its retirement rules, the append-only C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim.

Vocabulary used throughout:

- A *device window* is one fixed platform register range: the UART window `0x1000_0000`/`0x100`, or the HTIF endpoint `0x4000_8000`/8.
- A *device target* is a `BlockingDeviceTarget`: the object that owns one window's register state and answers its transactions.
- The *in-tree target* is the Rust device that answers a window today; the *host target* is one the C ABI supplies.
- A *device transaction* is one validated physical request routed to a device window, carried as one `BlockingTransaction` with `BlockingInitiator` provenance.
- A *device event* is the at-most-one guest-visible effect a device transaction reports beyond its register result: a UART transmit byte or an HTIF write value.
- A *host view* is a Platform read or write of device state outside any transaction: `Platform::uart_inspection`, `Platform::receive_uart`, or a typed `MemoryInterface` read of the window.
- A *parity run* is the same guest with no host device target, on the same route and with the same options.

| Decision | Accepted selection |
| --- | --- |
| D1. Delivery | One bounded cut of roadmap Stage 7: the UART and HTIF windows become blocking device targets on the TLM route, in Rust first, then the C ABI, then the SystemC host, then the exit work. The in-tree Rust device is the default target for each window, and the UART window may be served by the SystemC host. CLINT, PLIC and the simulator-only PLIC gateway are not device targets: the Platform owns `mtime`, `mtimecmp`, the four interrupt lines and the gateway reconciliation, so a target must not own them (D3). The native and flat routes, the CLI defaults, the guest suite, the RAM target, direct memory, the quantum and the non-blocking AT path are unchanged. No simulator behavior changes on the native route beyond the single event-publication site D4 names, which produces the same bytes in the same order. |
| D2. Selection and shape | `MachineConfig` gains a public `devices: DeviceTargets` field; `MachineConfig::new` selects `DeviceTargets::none()`. `src/blocking/device.rs` adds `BlockingDeviceTarget`, `BlockingDeviceEvent` and `DeviceTargets`. `BlockingDeviceTarget` has three methods, all `&self`: `b_transport(&self, &mut BlockingTransaction<'_>)`, `receive(&self, byte: u8)`, and `transport_reset(&self) -> bool`. A device transaction reuses `BlockingTransaction` so the status mapping, payload-change detection, provenance and response bytes have one implementation; its `may_suspend` is always false, its request `local_offset` is zero, and its response `delay`, `host_elapsed` and `dmi_allowed` are always zero. A device target that changes the payload, reports more than one event, sets any of those three response fields, or is handed an atomic envelope is a protocol failure of that access; a RAM target that reports a device event is the same failure, because only a device window publishes one. `DeviceTargets` carries one optional UART target in this contract and is the shape a later window extends; a selection requires `Transport::Tlm` and `PlatformKind::Native`, and `MachineError::UnsupportedTransport` is widened to name that case. The added public field breaks struct-literal construction by external code, and the CHANGELOG states that. `BlockingTarget`, `ruscv_machine_create` and `BlockingTransaction`'s request fields are otherwise unchanged, and the transaction gains only the device-event slot. |
| D3. Windows and in-tree targets | Two windows are device targets. **UART**: the in-tree target wraps the existing `Uart16550`; the Platform keeps today's window policy before the target, so byte-only width, fetch rejection, the `0x100` window and the eight-byte device range keep their current answers and diagnostics (`src/executor.rs:929-981`), and the native branch and the in-tree target share one register helper so the two routes cannot answer differently. **HTIF**: the in-tree target serves the dword read as zero and the dword write as an accepted write with one `HtifWrite` event; the exact-start, dword-width and fetch rules stay in the Platform, and the atomic RMW envelope stays in the Platform, is still never a device transaction, and keeps its old value of zero (`src/executor.rs:983-1046`, `:1136-1189`). **Not targets**: CLINT (`mtime`/`mtimecmp`/`msip`), PLIC (priority, pending, enable, threshold, claim/complete, contexts) and the source-1 gateway word at `0x4000_0000`. They stay `SystemBus` state on both routes with today's width, alignment and flush rules, because they own Platform time, the presented lines and the gateway's retraction rule; a device target cannot own them without moving time or line authority out of the Platform (ADR-0003, ADR-0004). Host replacement is offered for the UART window only; the HTIF window is an in-tree target in this contract, and host HTIF service is retained direction. |
| D4. Ordering, accounting and events | A Hart-origin device access still flushes the local offset under the bus lock before the target sees it (quantum F1, `src/executor.rs:905-915`), so a device transaction observes committed Platform time and can neither read nor move the offset; a `DebugInbound` access runs at a debug boundary, where the offset is already zero. The register side effects happen once, inside the one access, in request order. A device transaction adds nothing to `transport_delay_femtoseconds`, `host_elapsed_femtoseconds`, `mcycle`, `minstret`, the turn completion bound or a grant's horizon: annotation is fixed at zero and a non-zero value is a protocol failure (D2). It therefore adds no committed or local time, and the quantum and grant arithmetic keep their parity values; the F1 flush that precedes a Hart device access is today's rule, is unchanged, and commits only offset a turn had already accrued. The Platform publishes a response's device event only for an `Ok` status; an event attached to any other status is a protocol failure of that access, and an unknown completion keeps the precedence the archived non-blocking contract's D4 step 1 gave it, so nothing is published. `UartTransmit(byte)` pushes `PlatformEvent::UartTransmit(byte)` and calls `config.uart_output(byte)`; `HtifWrite(value)` pushes `PlatformEvent::HtifWrite(value)`; the event's value is the transaction's write payload. `Uart16550` gains a crate-internal `write_reg_reporting(offset, value) -> Option<u8>` that applies the write exactly as `write_reg` does and returns the byte when the write reached THR with DLAB clear, and `write_thr` keeps calling the output callback for other users. The in-tree target on the TLM route and the native route's UART branch call that one helper, `Platform::build` stops installing the output callback, and both events publish at the one site above, so a byte reaches `config.uart_output` once and before the store retires. An event that does not match its window is a protocol failure. |
| D5. Debug, SBA and host views | A `DebugInbound` request to a device window is the same device transaction with `BlockingInitiator::DebugInbound`, so a debugger and SBA see the same device state as the Hart; its delay and host elapsed must be zero and are not charged, a target fault maps to the existing normalized fault and `sberror` taxonomy, and a protocol or host failure keeps its current non-guest classification. The atomic path is unchanged and never reaches a target (D3). A host view of the in-tree UART keeps today's meaning: `uart_inspection` reads its state and `receive_uart` injects a byte. A host-served UART window has no Rust state to view, so `uart_inspection` returns `None`, `receive_uart` calls the target's `receive`, and a typed `MemoryInterface` read of that window returns `MemoryError::InvalidAddress` instead of reading a stale object; the C ABI never calls `receive` re-entrantly and never from another thread. The HTIF host view is unchanged: a typed read of the endpoint returns zero on both routes (`src/executor.rs:1204-1214`). Direct memory is never offered for a device window, and the protection is dispatch rather than a range check: `SystemBus` hands the RAM slot only a request whose whole span it has already matched as RAM (`src/executor.rs:876-903`), a device span takes the device path instead, a device target has no `get_direct_mem_ptr`, and the device path never sets `dmi_allowed` and never queries. `TlmRamAdapter` itself validates a grant's shape, address, permission and latency (`src/blocking/adapter.rs:857`) but does not clamp it to the image window, so the rule this contract states is that no request routed to a device can reach a direct-memory query or copy. |
| D6. Reset and lifecycle | A fresh `Platform` is built for every install (`src/machine/mod.rs:522`), which is the whole reset rule for an in-tree target. For a host target, `Platform::build` calls the selected target's `transport_reset` once, beside `RamSlot::begin_window` (`src/ram.rs:215`) and before the image is placed, and every reinstall takes the same path, including `fresh_reset`, `reload_for_ndmreset` and `ruscv_machine_reset`. A refused reset fails the build through the existing placement/lifecycle error channel and leaves the current association intact, exactly as a refused RAM transport reset does. No device transaction outlives a Platform: `b_transport` returns inside the instruction that issued it, so a reset cannot run under a live device callback. The event queue is per Platform, so a generation inherits no device event. |
| D7. Parity and determinism | With no host target, every guest's TLM pass keeps the exit code and byte-identical commit log of its native run, and its `mtime` sequence, `PlatformEvent` sequence including every `UartTransmit` byte, `config.uart_output` byte sequence and `BoundaryFacts` transport totals are identical to its parity run's, which is the same guest, route and options with no host target. `BoundaryFacts.quantum` is compared with the parity run of the same quantum selection and never with a native run, which has no quantum facts: a selected quantum reports its own ticks, syncs and reduced-accuracy flag, exactly as it does today. `hello` (`tests/bare-metal-riscv-test/rv64i/hello.S`) is in `PARITY_GUESTS` (`scripts/run_elf_tests.sh:74`) and the suite requires `Hello!` on every pass (`:116`), so the UART route's parity is already a suite condition. With a host UART, a run whose only device interaction is UART register access keeps the same exit code, byte-identical commit log and `mtime` sequence as its parity run, and its transmitted byte sequence equals the native run's: `hello` must transmit exactly `Hello!\n`, and that is the fixed point the smoke compares. A host UART adds no time, thread, wall clock or scheduling dependence: one access is one transaction, the sequence is the Hart's instruction sequence, and two runs of a guest with the same host target produce the same bytes, commit log and exit code. This contract makes no claim about a host target that models different register values from the in-tree device; the smoke's guest fixes the values that must agree. |
| D8. C ABI | Additive; `ruscv_machine_create` keeps its signature. `ruscv_payload` gains a final `int32_t device_event` and grows from 272 to 280 bytes; the event's value is read from the payload's write data, so no second field is needed. The payload's `delay_fs`, `local_offset_fs`, `host_elapsed_fs`, `may_suspend` and `dmi_allowed` must be zero in a device transaction, and a host that changes any is a protocol failure. The event tags are `RUSCV_DEVICE_EVENT_NONE` 0, `RUSCV_DEVICE_EVENT_UART_TRANSMIT` 1 and `RUSCV_DEVICE_EVENT_HTIF_WRITE` 2, and an event that does not match its window is a protocol failure. A new `ruscv_device` table carries `window_base`, `window_size`, `user`, `b_transport`, `receive` and `transport_reset`; `window_base` and `window_size` must equal the selected window's, and `user` must outlive the handle. A new entry `int32_t ruscv_machine_attach_device(ruscv_machine *machine, int32_t window, const ruscv_device *device)` takes `RUSCV_DEVICE_UART` 0; it must be called after create and before the first `ruscv_machine_load_elf`, it is refused with `RUSCV_ERROR_INVALID_ARGUMENT` for a NULL handle, NULL table or unknown window, and with `RUSCV_ERROR_CONFIG` for a mismatched base or size, a second attach for the same window, a late attach, or a handle whose `ruscv_target` is NULL and therefore has no TLM route. The table is copied at attach and the callbacks obey the RAM target's rules: creator thread only, no re-entry (every ABI entry reached from one returns `RUSCV_ERROR_REENTRANT`, except `ruscv_machine_invalidate_direct_mem`, which the direct-memory amendment keeps legal inside a callback), no waiting, no host time, and no exception across the boundary. Three layout pins move in the same change: `the_direct_memory_fields_are_final_in_their_structs` (`src/capi/tests.rs:1022`), the sizes and final fields in `tests/capi/smoke.c` (`:1259`, `:1266`, `:1281`) and the Layout rule and "final field" text of `include/ruscv_sim.h`. The CHANGELOG states that `ruscv_payload` grows and that a host must recompile. |
| D9. SystemC host and smoke | `integration/systemc` gains `--uart-target in-tree\|host`, default `in-tree`; a value other than those two is a usage error. Under `host` it builds a `UartTarget` that models the register set the suite's UART guest uses (RBR/THR, IER, IIR/FCR, LCR, MCR, LSR, MSR, SCR, DLL/DLM and a receive FIFO), attaches it through `ruscv_machine_attach_device`, answers with `RUSCV_TLM_OK` plus the transmit event on an accepted THR write, and counts device transactions, reads, writes and transmitted bytes at exit. Its `b_transport` is a plain C callback on the creator thread that never waits and never advances time. `scripts/test_systemc_smoke.sh` adds `hello` under `--isa rv64imafdc`, the profile the suite runs it with, and runs: both existing guests and `hello` under `--uart-target in-tree`, which must reproduce the existing facts and report zero host device transactions; `hello` under `--uart-target host`, which must show the native exit code, a byte-identical commit log, exactly `Hello!\n` transmitted, a non-zero transaction count equal to its read plus write count, and identical bytes on a second run; both existing guests under `--uart-target host`, which must reproduce their facts with zero device transactions because neither touches the UART; and `hello` under `--uart-target host` with `--dmi` and with `--nb`, which must keep the same facts as the matching in-tree pass. Each is a usage error without `--uart-target host`. |

## 3. Device ownership, ordering and events

The Platform keeps the window map, the pre-target policy, routing, the event queue and the presented lines; a device target owns one window's register state. The Machine owns admission, lifecycle and reset. The Hart is unchanged and never sees a target, a transaction or an event. The C ABI carries one table per window and the in-tree targets are the reference behavior a host target must reproduce for the guests the smoke runs.

| Window | Base and size | Today | This contract |
| --- | --- | --- | --- |
| UART | `0x1000_0000`, `0x100` | `SystemBus` `Uart16550`, byte-only raw access, callback publication (D1) | In-tree device target by default, host target through the C ABI; the same pre-target policy and one event publication site |
| HTIF | `0x4000_8000`, 8 | `SystemBus` endpoint: dword read zero, dword write fires the callback, atomic RMW envelope (D1) | In-tree device target for the plain dword read and write; the atomic envelope stays in the Platform |
| CLINT | `0x0200_0000`, `0xC000` | `SystemBus` `Clint`; `mtime`, `mtimecmp`, `msip`, MTIP/MSIP | Unchanged on both routes; not a device target |
| PLIC | `0x0C00_0000`, `0x40_0000` | `SystemBus` `Plic`; priority, pending, enable, threshold, claim/complete, MEIP/SEIP | Unchanged on both routes; not a device target |
| Source-1 gateway | `0x4000_0000`, 4 | `SystemBus` level word and its pending reconciliation | Unchanged on both routes; not a device target |

The next table is the complete rule for D4 and D5. `may_suspend` false means a true flag or a non-zero host elapsed time is D4's protocol failure of that access. Zero delay means any annotation is a protocol failure. "No" in the direct-memory column means no query is issued and no grant can cover the address.

| Request | Carrier | `may_suspend` | Delay and host elapsed | Charged | Device event | Direct memory |
| --- | --- | --- | --- | --- | --- | --- |
| Hart UART access (read or write) | One device transaction | false | Must be zero | No | One on an accepted THR write, none otherwise | No |
| Hart HTIF dword read or write | One device transaction | false | Must be zero | No | One `HtifWrite` on an accepted write | No |
| Hart HTIF AMO envelope | Platform's atomic path, never a target | — | — | No | One `HtifWrite` for the write side, as today | No |
| `DebugInbound` (SBA) access to a device window | One device transaction | false | Must be zero | No | Same rule as the Hart row | No |
| CLINT, PLIC or gateway access | Today's `SystemBus` branch | — | — | No | None | No |
| Host view (`uart_inspection`, `receive_uart`, typed read) | Target method or in-tree state | — | Must be zero | No | None | No |
| RAM access | RAM slot's `BlockingTarget`, unchanged | nb D3 rule | nb D4 rule | nb D4 rule | Must be none; a RAM target that reports one is a protocol failure | direct-memory D3 |

| `device-u1-native-event` | Event publication on the native route | Native `hello` delivers every transmitted byte to its `config.uart_output` sink | U1 |
| `device-u1-zero-delay` | Zero-delay check in the device adapter | A device target that annotates one tick is a protocol failure and `platform_mtime` is unchanged | U1 |
| `device-u1-zero-elapsed` | Zero-host-elapsed check in the device adapter | A device target that reports host elapsed time is a protocol failure | U1 |
| `device-u1-dmi-hint` | `dmi_allowed` check in the device adapter | A device target that sets the hint is a protocol failure and no grant is cached | U1 |
| `device-u1-htif-zero-read` | HTIF read in the in-tree target | An HTIF dword read returns zero on the TLM route, as on the native one | U1 |
| `device-u1-sba-initiator` | Initiator passed by the device routing | An SBA read of a UART register carries `DebugInbound` | U1 |
| `device-u2-native-refused` | Build refusal for a device target | A device target on the native route is `MachineError::UnsupportedTransport` | U2 |
| `device-u2-reset` | Device `transport_reset` call in `Platform::build` | A host target's state does not survive a reinstall | U2 |
| `device-u2-uart-view` | `uart_inspection` for a host-served window | `uart_inspection` is `None` for a host target and reads the in-tree device otherwise | U2 |
| `device-u3-abi-attach` | Attach table storage in the handle | A C device target's transaction count is non-zero | U3 |
| `device-u3-abi-event` | Device-event copy from the ABI response | An `HTIF_WRITE` tag on the UART window fails the run as a protocol failure, because the copied tag no longer matches its window | U3 |

SystemC fault-option controls are not mutation-runner cases, because that runner runs only `cargo test --offline --all-features` and D10 keeps `--all-features` free of a C++ toolchain. U4 owns them as options of the smoke binary in the style of `--fault-keep-offset`. `scripts/test_systemc_smoke.sh` runs each with its own failure assertion, and a run that passes with one set is a smoke failure:

- `--fault-uart-no-lsr`: `UartTarget` answers `LSR` with the transmit-empty bit clear. `hello` must exhaust its cycle bound and fail rather than pass.
- `--fault-uart-wait`: `UartTarget::b_transport` waits one tick. The run must report a failure whose diagnostic names host elapsed time on a device transaction.
- `--fault-uart-event-on-fault`: `UartTarget` reports a transmit with `RUSCV_TLM_ADDRESS_ERROR`. The run must fail as a protocol failure of that access, and no byte may reach the host's console.

Keep the mutation patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No SystemC-modeled interrupt line or interrupt controller, no device target for CLINT, PLIC or the source-1 gateway, no host HTIF service, no device delay annotation, no device host-time suspension, no device direct memory, no device atomic envelope, no non-blocking device transport or device phases, no more than one outstanding device transaction, no DMA, multi-Hart, arbitration or coherence, no second RAM target, no inbound master other than the existing DM, no `tlm::` `TlmBus` routing on the public path, no change to the native route's device answers, no checkpoint or restore, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile. Issue #207 stays open outside this contract.

Retained direction, each needing its own approved contract: host HTIF service through the same window-indexed table; device delay and host-time annotation with the turn bound and grant horizon extended to match; CLINT or PLIC targets only if time and line authority move under an accepted ADR amendment; SystemC-modeled interrupt lines; and a UART inspection snapshot for a host-served window.

## 6. Activation boundary

This documentation-only rotation archives the non-blocking contract, applies the bounded 2026-11-07 device-target amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle. Later implementation must meet the units above on its own reviewed commits.
