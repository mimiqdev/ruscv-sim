## 1. Objective and inherited profile

Let the SystemC host serve the Hart's guest-RAM transactions through the IEEE 1666 non-blocking base protocol, with SystemC time passing while a transaction is outstanding, and keep one synchronous Hart access per transaction with no second Hart execution path. Every host time that passes inside a transaction is charged to Platform time once, through the existing delay path, so the kernel still commits exactly what the Machine consumed. A run whose target takes no host time is exactly today's run.

The inherited profile is everything delivered through the completed quantum contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the quantum, the `capi` C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim.

Vocabulary used throughout:

- *Host time* is the external kernel's clock, `sc_time_stamp()` in the SystemC host. Rust has no host time of its own.
- A *suspending target* is one whose new `BlockingTarget::suspends_host_time()` is true. Only it may let host time pass inside a transaction callback.
- A *charged transaction* is a Hart-initiated `b_transport` request issued while the adapter's guest-turn accounting is open, between `TlmRamAdapter::begin_turn` and `take_turn_delay` (`src/blocking/adapter.rs`), so its delay is charged to Platform time under the 2026-11-04 ADR-0004 amendment. Fetches, data accesses, atomic envelopes and Sv39 walk reads and A/D envelopes of a guest turn are charged transactions. A `DebugInbound` request, a Debug Mode access through the Hart port (abstract command or program buffer), which `OwnedMachine::debug_boundary` runs outside that window, a debug transport request, a transport reset, a direct-memory query and a direct copy are not.
- `may_suspend` is a request flag that is true exactly for a charged transaction to a suspending target.
- `e`, the *host elapsed* time, is a response field: the host time, in exact femtoseconds, that passed between the callback's entry and its return.
- `d` is the existing response delay. It now counts from the transaction's issue, so it includes `e` plus any annotated remainder the callback did not wait.
- `W` is a grant's host elapsed time: the sum of `e` over that grant's charged transactions.
- The *base protocol* is the IEEE 1666 TLM-2.0 base protocol of `nb_transport_fw` and `nb_transport_bw`, with phases `BEGIN_REQ`, `END_REQ`, `BEGIN_RESP` and `END_RESP`.
- The *AT path* is the SystemC initiator serving a `may_suspend` transaction through the base protocol. `λ` is the latency of the RAM target's AT mode, from `BEGIN_REQ` to `BEGIN_RESP` in host time.
- A *parity run* is the same run with `--nb` off, which uses `b_transport` only.

| D2. Selection | `BlockingTarget` gains `fn suspends_host_time(&self) -> bool` with a default of `false`, so existing implementors compile and behave as today. `ZeroDelayRam` keeps the default. `TlmRamAdapter` reads it once at construction. A suspending target with a non-zero `MachineConfig.quantum` is the existing `MachineError::UnsupportedTransport`, whose message is widened to name this case. The reason is that host time passing inside a grant would stop the quantum anchor `E` from being the kernel's clock for the whole grant (archived quantum D12). A suspending target composes with `dmi`. `MachineConfig` gains no field and the CLI gains no option, because no CLI target suspends. `BoundaryFacts` gains `host_elapsed_femtoseconds: u64`, cumulative for the generation like `transport_delay_femtoseconds`; its manual `Default` (`src/machine/mod.rs`) gains zero. | D3. Marking | `BlockingTransaction` gains a read-only `may_suspend() -> bool` request accessor. The adapter sets it at issue time from three facts: the target suspends, the initiator is `BlockingInitiator::Hart`, and the guest-turn accounting is open (`AdapterState::active`). It is therefore false for every request that is not a charged transaction, including Debug Mode Hart-port work, which runs at a debug boundary after `take_turn_delay` has closed the window. It is false for every request to a non-suspending target. It is timing metadata only: address, bytes, status and permissions never depend on it, and `ZeroDelayRam` ignores it. A direct copy has no transaction and needs no flag. |
| D4. Host elapsed and charging | `BlockingTransaction` gains a `set_host_elapsed(Femtoseconds)` response setter and a `host_elapsed()` accessor, and `e` starts at zero. A *terminal* response is one whose status is not `Incomplete`: `Ok`, a guest-visible fault status or `GenericError`. The adapter keeps its existing response order and extends it with six steps. One response-classification helper, shared by the plain and atomic response paths of `src/blocking/adapter.rs`, implements steps 1, 2 and 4–6, so each step has one site. (1) A target panic, or a response carrying the outcome-unknown flag, is an unknown completion that poisons the transport as today, whatever `e`, `d` or `may_suspend` it carries. It is charged its `e`. No later step, overshoot error or accounting error reclassifies it, so the access stays an unknown completion. (2) A changed request payload is a protocol failure as today, charged `e`. (3) The committed-write record and the direct-memory D7 store-conditional gate are applied exactly as today, before the steps below. A written `Ok` response that then fails a step is therefore still recorded (ADR-0002 §6). (4) The *unmarked-elapsed rule*: a non-zero `e` on a request whose `may_suspend` is false is a protocol failure, charged `e`. (5) The *elapsed-above-delay rule*: a terminal response with `e > d` is a protocol failure, charged `e`. Under steps 2, 4 and 5 the step's protocol failure is the reported classification. The charge is still taken, and an overshoot or accounting error it raises is appended to that failure's diagnostic, never reported in its place. (6) Otherwise the response is classified as today. A terminal response is charged `d`, including a fault status, with today's malformed-delay and overshoot checks. An `Incomplete` response keeps today's checks of its uncounted `d`, so a malformed or above-maximum `d` is still today's host failure. If those checks pass, it is charged `e`, because its annotation is still not trusted but host time that has passed is a fact. Every charge goes through the one `account_delay` path: the same per-access round-up of `to_platform_ticks` (`src/blocking/mod.rs`), the same declared-maximum overshoot rule, still consumed by the failed turn, and the same turn bound. `account_delay` counts nothing outside the guest-turn window, so debug work stays uncharged as today. `e` never enters `mcycle` or `minstret`. For every transaction whose charge `account_delay` counts, its `e` is added in exact femtoseconds to the host-elapsed total behind `host_elapsed_femtoseconds`, whichever amount was charged; a transaction it does not count adds nothing. With a non-suspending target that takes no host time, `e` is zero and every path is today's. |
| D5. Grant commit rule | `ruscv_grant` gains a final `uint64_t host_elapsed_fs`: the grant's `W`, the increase of `host_elapsed_femtoseconds` from the grant's start to its return, never the cumulative value. The `e` of every counted transaction lands in a turn of the same grant, its charge is either `d >= e` or `e` itself, and the round-up only raises a charge, so `host_elapsed_fs <= consumed_fs` for every grant whose committed time did not fall. `host_elapsed_fs` is set for every grant, zero for a grant that ran no turn, unlike `facts.transport_delay_fs`, which only a turn updates. A host waits exactly `consumed_fs - host_elapsed_fs` after a grant, which leaves its clock at `committed_end_fs`, and keeps its existing check of that equality after every grant. Two cases can break the inequality. One is a turn refused by the clock-overflow rule, whose advance does not reach `mtime` (archived quantum D4); that run has already failed. The other is a guest store that lowers `mtime` inside a grant. That is open issue #207: the existing unsigned `consumed_fs` subtraction in `run_grant_inner` misbehaves there before this rule applies, and this contract does not change it. A host that reads `host_elapsed_fs > consumed_fs` commits nothing more and classifies the run as a host failure unless it has already failed. With `W` = 0 the rule is today's `wait(consumed_fs)`. Time fidelity is bounded accordingly. Inside a grant the kernel clock has advanced only by the host time already passed in that grant's transactions, so it lags the Hart's local time by the grant's uncommitted ticks. A target must not treat `sc_time_stamp()` inside a callback as the Hart's time; the two agree only at a grant's end, after the wait. |
| D6. C ABI | Additive under the header's append-only rule, so `ruscv_machine_create` keeps its signature. As with the quantum, earlier offsets hold but sizes change, so the ABI is not binary-compatible with the previous header and the CHANGELOG states that a host must recompile. `ruscv_target` gains a final `int32_t suspends_host_time` and grows from 56 to 64 bytes; nonzero selects a suspending target, the table is copied at create and the value persists across `ruscv_machine_reset`. `ruscv_payload` gains a final `int32_t may_suspend` request field and a final `uint64_t host_elapsed_fs` response field and grows from 256 to 272 bytes. `ruscv_grant` gains the D5 field after `facts` and grows from 128 to 136 bytes. A suspending table with a non-zero `quantum_ticks` is `RUSCV_ERROR_CONFIG` from `ruscv_machine_create`, through `host::validate_target` or `host::validate_quantum`. A NULL table selects the native route, which never suspends. The layout pins change in the same change. `the_direct_memory_fields_are_final_in_their_structs` (`src/capi/tests.rs`) and the layout checks in `tests/capi/smoke.c` move to the new final fields. Both gain a `ruscv_grant` size and final-field pin, which neither has today. The Layout rule and "final field" text of `include/ruscv_sim.h` name the new final fields. The thread rule is narrowed. A `b_transport` callback whose payload has `may_suspend` set may suspend the calling process and let host time pass, provided it resumes and returns on the creator thread. While it is suspended, the thread-local callback flag (`src/capi/mod.rs`) stays set. So every ABI entry that another process on that thread makes and that reaches the callback check returns `RUSCV_ERROR_REENTRANT`, except `ruscv_machine_invalidate_direct_mem`. That includes `ruscv_machine_destroy` on a live handle. An entry that fails its argument checks first, or `ruscv_machine_destroy(NULL)`, keeps its existing result. A call from another OS thread is still `RUSCV_ERROR_NOT_CREATOR_THREAD`. A host must not stop or tear down its kernel, kill or reset the suspended process, or destroy the handle while a callback is suspended. Destroy is refused then, so a host that breaks the rule leaks the handle and never frees it under a live frame. Every other callback (`transport_dbg`, `transport_reset`, `get_direct_mem_ptr`, and `b_transport` with `may_suspend` clear) still must not wait or advance host time. |
| D7. SystemC initiator | `integration/systemc` gains `--nb`, which sets `suspends_host_time` in the table; `--nb-latency` or `--nb-path` without `--nb` is a usage error. For a payload with `may_suspend` set, `RuscvInitiator` runs the base protocol on its socket with one transaction outstanding, from the callback's own process, the driver `SC_THREAD`. That process sends `BEGIN_REQ` on `nb_transport_fw` with zero delay and is the only process that waits. A forward return of `TLM_ACCEPTED` leaves the next phase to the backward path. A forward return of `TLM_UPDATED` with `END_REQ` or `BEGIN_RESP`, or of `TLM_COMPLETED`, takes effect after its annotated delay, which the process waits. `nb_transport_bw` runs in the target's process and never waits. It records the phase with its effective time, the current host time plus the annotated delay, and notifies the waiting process's event. An `sc_event` keeps only its earliest pending notification, so the waking process acts only on recorded phases whose effective time has arrived and re-arms for any later one; a phase never takes effect early. `nb_transport_bw` returns `TLM_ACCEPTED` for `END_REQ`. For `BEGIN_RESP` it returns `TLM_COMPLETED`, which ends the transaction with no forward `END_RESP`. After a forward return of `TLM_UPDATED` with `BEGIN_RESP` takes effect, the process sends `END_RESP` on `nb_transport_fw` with zero delay, which ends the transaction whatever that call returns. A `BEGIN_RESP` that arrives before `END_REQ` also ends the request. With one outstanding transaction the initiator holds at most two recorded phases and needs no payload event queue. The transaction completes at the host time its `BEGIN_RESP` or forward `TLM_COMPLETED` takes effect. The initiator reports `d = e`, the host time from `BEGIN_REQ` to completion, so no annotated remainder is left. The status, bytes, atomic response half and `dmi_allowed` hint come from the transaction. The transaction is initiator-owned: a generic payload with a memory manager and its own data and extension storage. Request bytes are copied in before `BEGIN_REQ` and response bytes copied out at completion, so no target ever sees the ABI's buffer. A payload with `may_suspend` clear, and every payload without `--nb`, takes `b_transport` as today. On every `b_transport` the initiator measures `e` around the call and reports it, so D4's unmarked-elapsed rule catches a target that waits there, and `mark_unknown_completion` keeps the measured `e` instead of only zeroing the delay. The measurement is kept where the exception wrapper that calls `mark_unknown_completion` can read it. The initiator also measures host time around `transport_dbg`, `transport_reset` and `get_direct_mem_ptr`. One that lets host time pass becomes a failed debug transfer, an unacknowledged reset or `RUSCV_DMI_FAILED`. `MachineDriver::run` creates the handle and drives it from one `SC_THREAD`. When a suspended callback resumes, the initiator checks that `std::this_thread::get_id()` is still the creator thread and reports an unknown completion if it is not. The pinned SystemC 3.0.2 build uses its default coroutine package, under which every `SC_THREAD` runs on the kernel's OS thread. No build pin excludes pthread processes, so that runtime check is the guard, and a SystemC build with pthread processes is unsupported. The grant loop waits `consumed_fs - host_elapsed_fs` (D5). `--nb` with a non-zero `--quantum` is refused by `ruscv_machine_create`, and the host reports that as a host failure. `--nb` composes with `--dmi` and `--dmi-invalidate-every`. Callbacks other than `ruscv_machine_invalidate_direct_mem` still never re-enter the ABI. |
| D8. RAM target AT mode | Under `--nb`, `RamTarget` also registers `nb_transport_fw`; its `b_transport`, `transport_dbg` and direct-memory grants are unchanged. `--nb-latency <fs>`, default 0, sets `λ` and the table's declared maximum `max_delay_fs` to `λ`; a value above 10^15 fs (1 s) is a usage error, so no timeout or fault offset can overflow. `--nb-path accepted|updated|early|annotated|completed`, default `accepted`, selects the target's return path. Every path applies the access exactly as its `b_transport` does: the same storage, atomic table, version clock and hint, once, inside the `nb_transport_fw` call that carries `BEGIN_REQ`. Later phases carry only timing, so no phase can change RAM after it is sent. With one outstanding transaction and the Hart blocked in its callback, no other access can observe the difference from applying it at `BEGIN_RESP`. The target schedules its own phases through a `peq_with_cb_and_phase`, which carries the phase. Under `accepted` it returns `TLM_ACCEPTED`, then sends `END_REQ` on the backward path in a later delta at the same host time, and `BEGIN_RESP` `λ` after `BEGIN_REQ`, each with zero annotation. Under `updated` it returns `TLM_UPDATED` with `END_REQ` and sends `BEGIN_RESP` `λ` later with zero annotation. Under `early` it returns `TLM_UPDATED` with `BEGIN_RESP` and an annotated delay of `λ`. Under `annotated` it returns `TLM_ACCEPTED`, then in a later delta at the same host time sends `END_REQ` with zero annotation and at once `BEGIN_RESP` with an annotated delay of `λ`, so the initiator must hold a phase whose effective time is later than one already notified. Under `completed` it returns `TLM_COMPLETED` with an annotated delay of `λ`. A `BEGIN_RESP` answered with `TLM_COMPLETED` ends the transaction for the target, and a forward `END_RESP` is answered with `TLM_COMPLETED`. With `λ` = 0, `BEGIN_RESP` is delta-notified, so other processes run and host time does not move. While any phase it owes is still scheduled, `transport_reset` withholds its acknowledgement, so no fresh generation coexists with an outstanding phase. At exit it reports its `BEGIN_REQ` count and its applied-access count. |
| D9. Late responses and retirement | The initiator bounds each AT transaction by the declared maximum. Every wait of the callback's process is bounded by a timeout `max_delay_fs + 1` fs after `BEGIN_REQ`, so a completion at exactly the declared maximum, including a delta-notified one at `λ` = 0, is in time. A phase whose annotated delay would take effect after the timeout is late. A transaction not complete at the timeout is retired. `mark_unknown_completion` reports it with `outcome_unknown` set and with the time waited as `e`. D4 step 1 charges that `e`, the overshoot rule does not reclassify it, and the unknown completion poisons the transport. A retired transaction's storage stays allocated until the target has completed it or released every reference it acquired. A transaction the target had already completed on the forward path is released at once. Every later backward call that names a retired transaction is ignored and counted: `END_REQ` is answered with `TLM_ACCEPTED` and `BEGIN_RESP` with `TLM_COMPLETED`. Its bytes never reach the ABI. The target applied the access at `BEGIN_REQ` and withholds a reset acknowledgement while a phase is scheduled, so a late phase can change neither RAM nor a fresh generation. At every stop after a retirement, whether a terminal result or a host failure, the host first runs the kernel until the RAM target has no scheduled phase, under the smoke's wall-clock `timeout`, so every late phase is delivered and ignored. Only then does it destroy the handle and stop the kernel. At exit it reports the late-phase count. This is the Stage 7 exit standard that a failure or unknown completion cannot leave a late callback mutating state. |
| D10. Parity and time facts | With `λ` = 0 on every path, with and without `--dmi`, a run has the parity run's exit code, a byte-identical commit log, the same `consumed_fs`, `committed_end_fs` and grant count at every grant, and `host_elapsed_fs` zero. With `λ` > 0 a run keeps the exit code and the byte-identical commit log, because neither smoke guest reads `time`, `mtime` or a counter (U3 confirms this from their sources). Let `n` be the target's `BEGIN_REQ` count in a pass without `--dmi`. Then three sums hold over the run. `host_elapsed_fs` sums to `n` × `λ`. The final `transport_delay_fs`, an exact femtosecond total, equals `n` × `λ`. `consumed_fs` sums to the parity run's sum plus `n` × 2 ticks, because each 1.5-tick delay rounds up to two whole ticks of the 1 ns period. After every grant the kernel clock equals `committed_end_fs`. The smoke uses `λ` = 1500000 fs, 1.5 ticks, so every AT access exercises the round-up and the grant-end wait covers the half-tick remainder. |
| D11. CI and documentation | No new CI job and no dev-image change. Rust and C ABI tests run in `Quality and tests`. The SystemC passes and fault-option controls run in the existing `SystemC transport smoke` job, where every run keeps its wall-clock `timeout`. The §4 mutation cases run in `Debug mutation controls`; each reuses one focused test filter, so the runner stays well inside that job's 90-minute limit, and each unit's PR states the runner's duration on its head. `cargo build`/`test --all-features` still need no C++ toolchain. `docs/integration/systemc-tlm.md` becomes normative for suspension, the base-protocol mapping, the commit rule, retirement and the AT target mode. Its open items keep only TLM-modeled devices, SystemC-modeled interrupt lines and more than one outstanding transaction. The header, CHANGELOG, `integration/systemc/README.md` and verification docs state the ABI additions, `--nb`, `--nb-latency`, `--nb-path` and the fault options. The "must not advance time, wait" comment of `integration/systemc/ruscv_initiator.h` is narrowed to the D6 rule. |

## 3. Transaction classes

The Machine and Platform ownership is unchanged. The target declares whether it suspends. The Runner-side host owns the phases and its own clock. The Hart never sees a phase, a suspension or host time. The table is the complete rule for D3, D4 and D7. `e` must be zero means that a non-zero value is D4's unmarked-elapsed rule for a transaction, and that D7's initiator classification applies to a callback with no payload. An unknown completion is D4 step 1 in every row that has a transaction.

| Request | `may_suspend` | `e` | Charged |
| --- | --- | --- | --- |
| Charged transaction to a suspending target | 1 | At most `d` when terminal | `d` for a terminal response that passes D4, otherwise `e` |
| Charged transaction to a non-suspending target | 0 | Must be zero | `d` for a terminal response that passes D4, as today, otherwise `e` |
| `DebugInbound` request (SBA) | 0 | Must be zero | No, as today |
| Debug Mode Hart-port access (abstract command, program buffer) | 0 | Must be zero | No, as today |
| Direct copy | No transaction | No callback | Grant latency, as today |
| `transport_dbg` (image install, host views, `tohost` poll) | No payload | Must be zero | No |
| `transport_reset` | No payload | Must be zero | No |
| `get_direct_mem_ptr` | No payload | Must be zero | No |

SystemC fault-option controls are not mutation-runner cases, because that runner runs only `cargo test --offline --all-features` and D11 keeps `--all-features` free of a C++ toolchain. U4 owns them as options of the smoke binary in the style of `--fault-keep-offset`. `scripts/test_systemc_smoke.sh` runs each with its own failure assertion, and a run that passes with one set is a smoke failure. The first three run under `--nb --nb-latency 1500000` on `accepted` and are usage errors without `--nb`. `--fault-wait-blocking` and `--fault-wait-debug` run without `--nb` and are usage errors with it:

- `--fault-late-response`: `RamTarget` sends `BEGIN_RESP` one tick after the declared maximum. The run must report `result state=failed`. The failed boundary's `uncertain` flag must be 1, and its diagnostic must say the target could not establish the outcome. Before its drain, the host calls `ruscv_machine_reset` and requires a non-OK status, because the target withholds its acknowledgement. The late-phase count must be at least 1, and the applied-access count must equal the `BEGIN_REQ` count.
- `--fault-uncounted-elapsed`: the initiator reports `e` = 0 while it reports `d` as the host time that passed. The run must stop with a host failure whose diagnostic names the kernel clock that does not match the Machine cursor.
- `--fault-short-delay`: the initiator reports `d` one femtosecond below `e`. The run must report `result state=failed`, the failed boundary's `uncertain` flag must be 0, and its diagnostic must name host elapsed time above the response delay.
- `--fault-wait-blocking`: `RamTarget::b_transport` waits one tick before it answers. The run must report `result state=failed`, the failed boundary's `uncertain` flag must be 0, and its diagnostic must name host elapsed time on a request that may not suspend.
- `--fault-wait-debug`: `RamTarget::transport_dbg` waits one tick. Image installation must fail, and the host must report a failure of `ruscv_machine_load_elf`.

Keep the mutation patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No Rust non-blocking trait or phase type, more than one outstanding transaction or pipelining, a payload event queue in the initiator, non-blocking transport for any device, TLM-modeled CLINT/PLIC/UART/HTIF, SystemC-modeled interrupt lines, a suspending target combined with a quantum, `tlm_quantumkeeper` or `tlm_global_quantum`, a CLI or guest-suite non-blocking option, suspension inside debug transport, transport reset or a direct-memory query, a non-Machine initiator on the RAM target, multi-Hart or DMA, inbound masters other than the existing DM, a SystemC build with pthread processes, non-Linux FFI targets, checkpoint and restore, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile. Issue #207 stays open outside this contract.

TLM-modeled devices and SystemC-modeled interrupt lines need their own contract. Stage 8 remains conditional.

## 6. Activation boundary

This documentation-only rotation archives the quantum contract, applies the bounded 2026-11-07 non-blocking-transport amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle.
