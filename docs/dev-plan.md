## 1. Objective and inherited profile

Let the SystemC host serve the Hart's guest-RAM transactions through the IEEE 1666 non-blocking base protocol, with SystemC time passing while a transaction is outstanding, and keep one synchronous Hart access per transaction with no second Hart execution path. Every host time that passes inside a transaction is charged to Platform time once, through the existing delay path, so the kernel still commits exactly what the Machine consumed. A run whose target takes no host time is exactly today's run.

The inherited profile is everything delivered through the completed quantum contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the quantum, the `capi` C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim.

Vocabulary used throughout:

- *Host time* is the external kernel's clock, `sc_time_stamp()` in the SystemC host. Rust has no host time of its own.
- A *suspending target* is one whose new `BlockingTarget::suspends_host_time()` is true. Only it may let host time pass inside a transaction callback.
- A *charged transaction* is a Hart-initiated `b_transport` request issued while the adapter's guest-turn accounting is open, between `TlmRamAdapter::begin_turn` and `take_turn_delay` (`src/blocking/adapter.rs`), so its delay is charged to Platform time under the 2026-11-04 ADR-0004 amendment. Fetches, data accesses, atomic envelopes and Sv39 walk reads and A/D envelopes of a guest turn are charged transactions. A `DebugInbound` request, a Debug Mode access through the Hart port (abstract command or program buffer), which `OwnedMachine::debug_boundary` runs outside that window, a debug transport request, a transport reset, a direct-memory query and a direct copy are not.
- `may_suspend` is a request flag that is true exactly for a charged transaction to a suspending target.
- `e`, the *host elapsed* time, is a response field: the host time, in exact femtoseconds, that passed between the callback's entry and its return.
- `d` is the existing response delay. It now counts from the transaction's issue, so it includes `e` plus any annotated remainder the callback did not wait.
- `W` is a grant's host elapsed time: the sum of `e` over that grant's charged transactions.
- The *base protocol* is the IEEE 1666 TLM-2.0 base protocol of `nb_transport_fw` and `nb_transport_bw`, with phases `BEGIN_REQ`, `END_REQ`, `BEGIN_RESP` and `END_RESP`.
- The *AT path* is the SystemC initiator serving a `may_suspend` transaction through the base protocol. `λ` is the latency of the RAM target's AT mode, from `BEGIN_REQ` to `BEGIN_RESP` in host time.
- A *parity run* is the same run with `--nb` off, which uses `b_transport` only.

| Decision | Accepted selection |
| --- | --- |
| D1. Delivery | One bounded cut of roadmap Stage 7: non-blocking transport for the guest-RAM target in the SystemC host, made possible by suspending transactions across the C ABI. Rust comes first, then the C ABI, then the SystemC base protocol, then late-response retirement and the fault controls. The Hart, ISA, MMU, TLB, decoder and DM are unchanged: a Hart access stays one synchronous physical request and one transaction, and phases exist only inside the SystemC host. The native and flat routes, the CLI, the guest suite and the quantum are unchanged. No Rust non-blocking trait or phase type is added, because Rust has no kernel in which a phase could wait. |
| D2. Selection | `BlockingTarget` gains `fn suspends_host_time(&self) -> bool` with a default of `false`, so existing implementors compile and behave as today. `ZeroDelayRam` keeps the default. `TlmRamAdapter` reads it once at construction. A suspending target with a non-zero `MachineConfig.quantum` is the existing `MachineError::UnsupportedTransport`, whose message is widened to name this case. The reason is that host time passing inside a grant would stop the quantum anchor `E` from being the kernel's clock for the whole grant (archived quantum D12). A suspending target composes with `dmi`. `MachineConfig` gains no field and the CLI gains no option, because no CLI target suspends. `BoundaryFacts` gains `host_elapsed_femtoseconds: u64`, cumulative for the generation like `transport_delay_femtoseconds`; its manual `Default` (`src/machine/mod.rs`) gains zero. The CHANGELOG names every public addition and states that the new `BoundaryFacts` field breaks exhaustive struct literals. No other public signature changes. |
| D3. Marking | `BlockingTransaction` gains a read-only `may_suspend() -> bool` request accessor. The adapter sets it at issue time from three facts: the target suspends, the initiator is `BlockingInitiator::Hart`, and the guest-turn accounting is open (`AdapterState::active`). It is therefore false for every request that is not a charged transaction, including Debug Mode Hart-port work, which runs at a debug boundary after `take_turn_delay` has closed the window. It is false for every request to a non-suspending target. It is timing metadata only: address, bytes, status and permissions never depend on it, and `ZeroDelayRam` ignores it. A direct copy has no transaction and needs no flag. |
| D4. Host elapsed and charging | `BlockingTransaction` gains a `set_host_elapsed(Femtoseconds)` response setter and a `host_elapsed()` accessor, and `e` starts at zero. When the response arrives, before `account_delay`, the adapter applies four rules in order. (a) A non-zero `e` on a request whose `may_suspend` is false is a protocol failure of that access. (b) A response carrying the outcome-unknown flag stays an unknown completion and poisons the transport as today. (c) A completed response with `e > d` is a protocol failure. (d) Otherwise the response is classified as today. The charged delay is `d` for a completed response and `e` for any other outcome under (b), (c) and (d). An incomplete or unknown annotation is still not trusted, but host time that has passed is a fact. A non-zero `e` under (a) is charged only when the request is a charged transaction. Each charged delay goes through the one `account_delay` path: the same per-access round-up of `to_platform_ticks` (`src/blocking/mod.rs`), the same declared-maximum overshoot rule, still consumed by the failed turn, and the same turn bound. `e` never enters `mcycle` or `minstret`. Every `e` the adapter charges is added in exact femtoseconds to the host-elapsed total behind `host_elapsed_femtoseconds`, and debug work never adds to it. With a non-suspending target, `e` must be zero and every path is today's. |
| D5. Grant commit rule | `ruscv_grant` gains a final `uint64_t host_elapsed_fs`: the grant's `W`, the increase of `host_elapsed_femtoseconds` from the grant's start to its return, never the cumulative value. Every charged `e` lands in a turn of the same grant, and the round-up only raises a charge, so `host_elapsed_fs <= consumed_fs` for every grant whose committed time did not fall. A host waits exactly `consumed_fs - host_elapsed_fs` after a grant, which leaves its clock at `committed_end_fs`, and keeps its existing check of that equality after every grant. Two cases break the inequality, and each ends the run. One is a turn refused by the clock-overflow rule, whose advance does not reach `mtime` (archived quantum D4); that run has already failed. The other is a guest store that lowers `mtime` inside a grant, which is open issue #207 and outside this contract. A host that reads `host_elapsed_fs > consumed_fs` commits nothing more and classifies the run as a host failure unless it has already failed. With `W` = 0 the rule is today's `wait(consumed_fs)`. |
| D6. C ABI | Additive under the header's append-only rule, so `ruscv_machine_create` keeps its signature. As with the quantum, earlier offsets hold but sizes change, so the ABI is not binary-compatible with the previous header and the CHANGELOG states that a host must recompile. `ruscv_target` gains a final `int32_t suspends_host_time` and grows from 56 to 64 bytes; nonzero selects a suspending target, the table is copied at create and the value persists across `ruscv_machine_reset`. `ruscv_payload` gains a final `int32_t may_suspend` request field and a final `uint64_t host_elapsed_fs` response field and grows from 256 to 272 bytes. `ruscv_grant` gains the D5 field after `facts` and grows from 128 to 136 bytes. A suspending table with a non-zero `quantum_ticks` is `RUSCV_ERROR_CONFIG` from `ruscv_machine_create`, through `host::validate_target` or `host::validate_quantum`. A NULL table selects the native route, which never suspends. Three layout pins move in the same change: `the_direct_memory_fields_are_final_in_their_structs` (`src/capi/tests.rs`), the layout checks in `tests/capi/smoke.c`, and the Layout rule and "final field" text of `include/ruscv_sim.h`. The thread rule is narrowed. A `b_transport` callback whose payload has `may_suspend` set may suspend the calling process and let host time pass, provided it resumes and returns on the creator thread. While it is suspended, the thread-local callback flag (`src/capi/mod.rs`) stays set. So every ABI call made on that thread by any other process, including `ruscv_machine_destroy`, returns `RUSCV_ERROR_REENTRANT`, except `ruscv_machine_invalidate_direct_mem`. A call from another OS thread is still `RUSCV_ERROR_NOT_CREATOR_THREAD`. A host must not stop or tear down its kernel, kill or reset the suspended process, or destroy the handle while a callback is suspended. Destroy is refused then, so a host that breaks the rule leaks the handle and never frees it under a live frame. Every other callback (`transport_dbg`, `transport_reset`, `get_direct_mem_ptr`, and `b_transport` with `may_suspend` clear) still must not wait or advance host time. |
| D7. SystemC initiator | `integration/systemc` gains `--nb`, which sets `suspends_host_time` in the table. For a payload with `may_suspend` set, `RuscvInitiator` runs the base protocol on its socket with one transaction outstanding. It sends `BEGIN_REQ` on `nb_transport_fw` with zero delay. It honors every annotated delay by waiting it, which is exact with one outstanding transaction, so the initiator needs no payload event queue. It accepts `TLM_ACCEPTED`, then waits for `END_REQ` and `BEGIN_RESP` on `nb_transport_bw`. It also accepts `TLM_UPDATED` with `END_REQ` or `BEGIN_RESP` and `TLM_COMPLETED`, and treats a `BEGIN_RESP` that arrives before `END_REQ` as also ending the request. It answers `BEGIN_RESP` by sending `END_RESP` on `nb_transport_fw`. It reports `d = e`, the host time from `BEGIN_REQ` to completion, so no annotated remainder is left. The status, bytes, atomic response half and `dmi_allowed` hint come from the transaction. The transaction is initiator-owned: a generic payload with a memory manager and its own data and extension storage. Request bytes are copied in before `BEGIN_REQ` and response bytes copied out at completion, so no target ever sees the ABI's buffer. A payload with `may_suspend` clear, and every payload without `--nb`, takes `b_transport` as today, and on every `b_transport` the initiator measures `e` and reports it, so D4 (a) catches a target that waits there. `transport_dbg`, `transport_reset` and `get_direct_mem_ptr` that let host time pass become a failed debug transfer, an unacknowledged reset and `RUSCV_DMI_FAILED`. `sc_main` creates the handle and drives it from one `SC_THREAD`, and when a suspended callback resumes, the initiator checks that `std::this_thread::get_id()` is still the creator thread and reports an unknown completion if it is not. Under the pinned build's default coroutine package every `SC_THREAD` runs on the kernel's OS thread, so the check holds; a SystemC build with pthread processes is unsupported. The grant loop waits `consumed_fs - host_elapsed_fs` (D5). `--nb` with a non-zero `--quantum` is refused by `ruscv_machine_create`, and the host reports that as a host failure. `--nb` composes with `--dmi` and `--dmi-invalidate-every`. Callbacks other than `ruscv_machine_invalidate_direct_mem` still never re-enter the ABI. |
| D8. RAM target AT mode | Under `--nb`, `RamTarget` also registers `nb_transport_fw`; its `b_transport`, `transport_dbg`, direct-memory grants and reset are unchanged. `--nb-latency <fs>`, default 0, sets `λ` and the table's declared maximum `max_delay_fs` to `λ`. `--nb-path accepted|updated|completed`, default `accepted`, selects the target's return path. Under `accepted` it returns `TLM_ACCEPTED`, sends `END_REQ` on the backward path in a later delta at the same host time, and sends `BEGIN_RESP` `λ` after `BEGIN_REQ`, both through a `peq_with_get`. Under `updated` it returns `TLM_UPDATED` with `END_REQ` and sends `BEGIN_RESP` `λ` later. Under `completed` it returns `TLM_COMPLETED` with an annotated delay of `λ`. It answers `END_RESP` with `TLM_COMPLETED`. Every path applies the access exactly as its `b_transport` does: the same storage, atomic table, version clock and hint, once, at `BEGIN_RESP` or at the `TLM_COMPLETED` return. With `λ` = 0, `BEGIN_RESP` is delta-notified, so other processes run and host time does not move. At exit it reports its `nb_transport_fw` count. |
| D9. Late responses and retirement | The initiator bounds each AT transaction by the declared maximum: it waits for completion with a timeout of `max_delay_fs + 1` fs from `BEGIN_REQ`, so a response at exactly the declared maximum, including a delta-notified response at `λ` = 0, is in time. A transaction not complete at that timeout is retired: it is reported through the existing `mark_unknown_completion` path with `outcome_unknown` set and `e` equal to the time waited. D4 (b) charges that `e`, the unknown completion poisons the transport, and unknown completion takes precedence over overshoot. A retired transaction's storage stays allocated until the target releases every reference it acquired. Every later backward call that names it is answered with `TLM_COMPLETED`, ignored and counted, and its bytes never reach the ABI. Before the host stops the kernel at a terminal result, it runs the kernel until the RAM target has no scheduled phase, under the smoke's wall-clock `timeout`, so a late phase is delivered and ignored. At exit it reports the late-phase count. This is the Stage 7 exit standard that a failure or unknown completion cannot leave a late callback mutating state. |
| D10. Parity and time facts | With `λ` = 0 on every path, with and without `--dmi`, a run has the parity run's exit code, a byte-identical commit log, the same `consumed_fs`, `committed_end_fs` and grant count at every grant, and `host_elapsed_fs` zero. With `λ` > 0 a run keeps the exit code and the byte-identical commit log, because neither smoke guest reads `time`, `mtime` or a counter (U3 confirms this from their sources). Its `host_elapsed_fs` summed over the run equals the AT transaction count times `λ`. Its charged transport delay equals that count times `λ` rounded up per access to whole ticks of the 1 ns period. After every grant the kernel clock equals `committed_end_fs`. The smoke uses `λ` = 1500000 fs, 1.5 ticks, so every AT access exercises the round-up and the grant-end wait covers the half-tick remainder. |
| D11. CI and documentation | No new CI job and no dev-image change. Rust and C ABI tests run in `Quality and tests`. The SystemC passes and fault-option controls run in the existing `SystemC transport smoke` job, where every run keeps its wall-clock `timeout`. The §4 mutation cases run in `Debug mutation controls`; each reuses one focused test filter, so the runner stays well inside that job's 90-minute limit, and each unit's PR states the runner's duration on its head. `cargo build`/`test --all-features` still need no C++ toolchain. `docs/integration/systemc-tlm.md` becomes normative for suspension, the base-protocol mapping, the commit rule, retirement and the AT target mode. Its open items keep only TLM-modeled devices and more than one outstanding transaction. The header, CHANGELOG, `integration/systemc/README.md` and verification docs state the ABI additions, `--nb`, `--nb-latency`, `--nb-path` and the fault options. |

## 3. Transaction classes

The Machine and Platform ownership is unchanged. The target declares whether it suspends. The Runner-side host owns the phases and its own clock. The Hart never sees a phase, a suspension or host time. The table is the complete rule for D3, D4 and D7. `e` must be zero means that a non-zero value is D4 (a) for a transaction, and that D7's initiator classification applies to a callback with no payload.

| Request | `may_suspend` | `e` | Charged |
| --- | --- | --- | --- |
| Charged transaction to a suspending target | 1 | At most `d` when completed | `d` when completed, otherwise `e` |
| Charged transaction to a non-suspending target | 0 | Must be zero | `d` when completed, as today |
| `DebugInbound` request (SBA) | 0 | Must be zero | No, as today |
| Debug Mode Hart-port access (abstract command, program buffer) | 0 | Must be zero | No, as today |
| Direct copy | No transaction | No callback | Grant latency, as today |
| `transport_dbg` (image install, host views, `tohost` poll) | No payload | Must be zero | No |
| `transport_reset` | No payload | Must be zero | No |
| `get_direct_mem_ptr` | No payload | Must be zero | No |

Other mutation-runner controls, with unit names prefixed `nb-u<n>-`:

- `suspends_host_time` defaulting to true, or `ZeroDelayRam` declaring it;
- `e` charged twice, or charged in addition to `d` for a completed response;
- `e` charged into `mcycle`, `minstret` or `transport_delay_femtoseconds` beyond the charged delay;
- debug work adding to `host_elapsed_femtoseconds`;
- `host_elapsed_fs` reported before the grant-return sync, or left non-zero for a grant with no suspending transaction;
- the outcome-unknown flag on a response with non-zero `e` classified as an overshoot instead of an unknown completion;
- `may_suspend` or `host_elapsed_fs` not reset to zero for the next transaction.

SystemC fault-option controls are not mutation-runner cases, because that runner runs only `cargo test --offline --all-features` and D11 keeps `--all-features` free of a C++ toolchain. U4 owns them as options of the smoke binary in the style of `--fault-keep-offset`. `scripts/test_systemc_smoke.sh` runs each with its own failure assertion, and a run that passes with one set is a smoke failure:

- `--fault-late-response`: `RamTarget` sends `BEGIN_RESP` one tick after the declared maximum. The run must report `result state=failed`, the failed boundary's `uncertain` flag must be 1, its diagnostic must name an unknown completion, and the late-phase count must be at least 1.
- `--fault-uncounted-elapsed`: the initiator reports `e` = 0 while it reports `d` as the host time that passed. The run must stop with a host failure whose diagnostic names the kernel clock that does not match the Machine cursor.
- `--fault-short-delay`: the initiator reports `d` one femtosecond below `e`. The run must report `result state=failed`, the failed boundary's `uncertain` flag must be 0, and its diagnostic must name host elapsed time above the response delay.

Keep the mutation patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No Rust non-blocking trait or phase type, more than one outstanding transaction or pipelining, a payload event queue in the initiator, non-blocking transport for any device, TLM-modeled CLINT/PLIC/UART/HTIF, SystemC-modeled interrupt lines, a suspending target combined with a quantum, `tlm_quantumkeeper` or `tlm_global_quantum`, a CLI or guest-suite non-blocking option, suspension inside debug transport, transport reset or a direct-memory query, a non-Machine initiator on the RAM target, multi-Hart or DMA, inbound masters other than the existing DM, a SystemC build with pthread processes, non-Linux FFI targets, checkpoint and restore, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile. Issue #207 stays open outside this contract.

TLM-modeled devices and SystemC-modeled interrupt lines need their own contract. Stage 8 remains conditional.

## 6. Activation boundary

This documentation-only rotation archives the quantum contract, applies the bounded 2026-11-07 non-blocking-transport amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge.
