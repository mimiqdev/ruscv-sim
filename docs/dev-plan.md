# Development Plan

**Current milestone on rotation merge:** Blocking TLM and SystemC Transport

**Status:** Current approved target, activated by this contract-rotation merge. Until that merge, `main` retains RV64GC Default Profile as Current. On merge this is the sole Current contract and the [entire RV64GC default-profile contract](archive/milestones/rv64gc-default-profile.md) becomes historical. Activation changes no simulator behavior and makes no implementation-completeness claim.

**Authority:** Normative milestone contract, constrained by accepted ADR-0001–0004 and their amendments through the 2026-11-04 blocking-transport amendments to ADR-0002, ADR-0003 and ADR-0004. Source code and behavioral tests establish implemented behavior; CI and PR history retain check and review outcomes.

**Approved:** 2026-11-04. After the RV64GC default, the owner selected TLM/SystemC integration (post-A7 roadmap Stage 7) as the next milestone under the delegation of full planning authority to the maintaining agent, who selected decisions D1–D12 below, all recommended choices. The [proposal entry](proposals/post-gc-blocking-tlm.md) is informational, not another current contract.

## 1. Objective and inherited profile

Make guest RAM replaceable by a blocking TLM transport without a second Hart execution path. A Machine selects either the existing native Platform route (the default, unchanged) or a TLM route in which RAM accesses, atomics and image installation go through a blocking `b_transport`-style target. The same public fixture produces equivalent architectural, fault, event and time facts under both. A narrow C ABI then lets one pinned SystemC kernel host the Machine and supply that RAM target, proven by one smoke fixture.

The inherited profile is everything delivered through the completed RV64GC default-profile contract: `rv64imafdc` as the default with `rv64ima`, `rv64imac` and `rv64imafd` selectable, M/S/U, the Stage 5 platform rules, Debug Specification 1.0 with program buffer and SBA, and zero-entry PMP plus Sv39. The existing `src/tlm` vocabulary (`TlmGenericPayload`, `TlmResponseStatus`, `ScTime`, `TlmTarget`) is component code with no public route; it cannot express the standard status set, extensions, debug transport or femtosecond delays, so this contract adds a separate blocking-transport adapter vocabulary and leaves `src/tlm` unchanged.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route.

## 2. Selected decisions

References: ISA Manual 20250508, Debug Specification 1.0 at `5695c0aaa7a3c228e14702e1268eb5a5e50e3cb8`, IEEE 1666-2023 (SystemC, including TLM-2.0), and Accellera SystemC 3.0.2 at commit `70b0fc8e4a74acc677b0fc73cea08f940c2115d5`. The OpenOCD, Spike and riscv-arch-test pins of the archived contract are unchanged.

Every decision below was approved on 2026-11-04 under the delegation recorded above.

| Decision | Accepted selection |
| --- | --- |
| D1. Delivery | One bounded first cut of roadmap Stage 7: a blocking Rust TLM RAM route, then a C ABI, then one pinned SystemC smoke. DMI, non-blocking transport, TLM-modeled devices and temporal decoupling are later contracts. |
| D2. Transport selection | The Platform's single guest-RAM slot, today the `SimpleMemory` that `SystemBus` shares with the typed route, the physical and atomic backends, the DM inbound port, image placement and the host views (`tohost` polling, `clear_tohost`, signature extraction, `read_mem`/`write_mem` and `Machine::memory()`), becomes a selection: native `SimpleMemory` (default, behavior unchanged) or a caller-supplied TLM RAM target. Every one of those users goes through the selected slot; none keeps a private RAM copy. The adapter records every completed write and AMO before returning, so ADR-0002 §6 committed-write visibility and SC invalidation stay on the ruscv-sim side. CLINT, PLIC, UART, the fixed HTIF endpoint at `0x4000_8000` and the simulator-only test device stay native Platform devices. `MachineConfig` gains a public `transport` field (`MachineConfig::new` selects native) holding the target as a shared `Arc` so `Clone` still holds; this breaks struct-literal construction of `MachineConfig`. The D7 boundary-fact field and the `Flat`-with-`tlm` configuration error are likewise additive changes to public types; the CHANGELOG names all three, and no other public signature changes. `tlm` requires `PlatformKind::Native`; `Flat` with `tlm` is a configuration error. `run --transport native\|tlm` exposes the selection on the CLI; `tlm` there uses an in-tree Rust RAM target that annotates zero delay. The `RiscVSimulator` and `load_and_run*` facades keep the native route; the CLI reaches the TLM route through one additive public entry point that runs a file under a given `MachineConfig`, which the CHANGELOG names. Hart, address map and DM rules are unchanged; ISA code never sees a transport type. |
| D3. Request mapping | A new adapter vocabulary, separate from `src/tlm`, models IEEE 1666 blocking transport: the seven standard response statuses, a payload whose status starts as `TLM_INCOMPLETE_RESPONSE`, ruscv-sim payload extensions, a target interface with `b_transport`, `transport_dbg`, transport reset and a declared per-transaction maximum delay (zero for the in-tree and SystemC RAM targets), and delays as exact femtoseconds with checked arithmetic. One `PhysicalRequest` becomes one `b_transport` transaction: explicit physical address, `Read`/`Write` command, data length equal to the access width, streaming width equal to the length, no byte enables and little-endian raw bytes. An extension carries the existing `PhysicalAccessKind` and the initiator (Hart or debug inbound); no new category taxonomy is added. Hart fetch, data and page-table/A-D accesses and debug SBA and program-buffer accesses to RAM all use it. The adapter never splits, merges, caches or retries an access. |
| D4. Status mapping | Per ADR-0002 §4: `TLM_OK_RESPONSE` is completion. `TLM_ADDRESS_ERROR_RESPONSE`, `TLM_COMMAND_ERROR_RESPONSE`, `TLM_BURST_ERROR_RESPONSE` and `TLM_BYTE_ENABLE_ERROR_RESPONSE` are guest-visible target faults (the access kind's access fault). `TLM_GENERIC_ERROR_RESPONSE` is a host failure. `TLM_INCOMPLETE_RESPONSE` left by the target, or a payload whose address, command or length the target changed, is a protocol failure. An outcome-unknown flag in the ruscv-sim extension, an adapter panic or a C++ exception is an unknown completion. Only target faults are guest-visible; no TLM status, `sc_stop` or callback return becomes a ruscv-sim terminal result. |
| D5. Atomics | LR, SC and every AMO cross the transport as one transaction with a ruscv-sim atomic payload extension that encodes the operation, width, ordering bits and the SC committed-write check as data, not as a Rust function pointer. The target applies the operation indivisibly within that one call and returns the old value and SC outcome. A target that does not accept the extension answers `TLM_COMMAND_ERROR_RESPONSE`, which is a load access fault for LR and a store/AMO access fault for SC and AMOs, as on native. Read-then-write emulation is forbidden. Reservations stay per-Hart architectural state. |
| D6. Image installation, host views and reset | After every transport reset and before installation, the Platform zero-fills the whole RAM window, so no prior run's contents survive. It installs ELF segments, polls RAM-resident `tohost` and serves the host RAM views through the target's debug transport (`transport_dbg` semantics: no delay, no side effects, not counted as a transaction), never through `b_transport`. A failed or short debug transport fails the load before the first turn during installation, and is a host failure, never guest-visible, during polling or a host view. An unknown completion poisons the transport: no further access is issued, and reset first obtains the target's transport-reset acknowledgement, then reinstalls the image. A target that tries to apply a held write after an unknown completion cannot change the reinstalled image. |
| D7. Delay and time | Native responses carry zero delay. A TLM response's annotated delay (exact femtoseconds) is converted to Platform ticks with a declared tick period (default 1 ns), exactly when representable and otherwise rounded up, per ADR-0004 §5.2; overflow or a malformed delay is an adapter failure. Each turn's conservative completion bound (ADR-0004 §7.2) includes the target's declared maximum delay; a response above it is reported with its overshoot as a simulator failure per §5.3. The delay is consumed per ADR-0004 §5.3 and advances the same Platform time (`mtime`) as completed turns, so timer behavior sees it. Delay of SBA accesses and of accesses made while the Hart is in Debug Mode (including program-buffer execution) is validated and converted the same way but is not charged to Platform time, preserving the 2026-10-28 and 2026-10-30 ADR-0004 amendments. `mcycle` and `minstret` never include it. The Machine reports the total consumed transport delay in its boundary facts (zero on native). The in-tree Rust and SystemC RAM targets annotate zero delay, so parity runs are time-equivalent; delay controls use a separate delaying test target. |
| D8. C ABI | A `capi` cargo feature adds a C ABI module plus a hand-written header `include/ruscv_sim.h`; so `Cargo.toml` crate types and every default build are unchanged. The static library is built with `cargo rustc --lib --features capi --crate-type staticlib`. Opaque handles; create (ISA profile, tick period and RAM target), load ELF, run one grant, read boundary facts and result, write the commit log to a path, reset, destroy. A grant carries an authoritative start time, a maximum end time and a turn budget, all in femtoseconds or turns; it returns the consumed time (Platform time advanced by turns, idle jumps and transport delay, in femtoseconds), the facts and whether the grant boundary was reached. A start earlier than the last committed time, except after reset, is an adapter failure (ADR-0004 §4.4). The RAM target is a table of C callbacks (`b_transport`, `transport_dbg`, transport reset) plus its declared maximum delay, with user data, valid until destroy. Calls are accepted only on the creating thread; callbacks run only synchronously inside a ruscv-sim call on that thread; any re-entry from a callback is rejected with an error code. Rust panics are caught at the boundary and poison the handle. Errors are integer status codes; no Rust or C++ exception crosses the ABI. Payload buffers are owned by Rust and valid only for the duration of one callback. |
| D9. SystemC host | The dev image builds Accellera SystemC 3.0.2 at the pinned commit with C++17 through a reviewed Dockerfile change. A small CMake project under `integration/systemc/` builds a RAM target module with a `simple_target_socket` (`b_transport`, `transport_dbg`, transport reset and the atomic extension, zero delay) and an initiator `SC_THREAD` that drives the Machine through the C ABI in bounded grants. Each grant starts at the current `sc_time_stamp()`; after it the thread calls `wait()` with the returned consumed time, and it calls `sc_stop` only after ruscv-sim reports a terminal result. The SystemC side commits global time only from the returned amount (ADR-0004 §4.4). Linux x86-64 only. |
| D10. Parity fixtures | Rust tests compare native and the Rust TLM route on widths 1/2/4/8, raw bytes, each D4 status, injected host/protocol/unknown completions, every AMO and LR/SC outcome, and a non-zero-delay control. The guest suite runs every guest a second time under `--transport tlm`; for the named parity set (`hello`, `s5_timer`, `s5_external`, `atomic_tohost_exit` and `fd_fma`, each under its declared profile) the `--log-commits` output is byte-identical to native. The SystemC smoke runs `atomic_tohost_exit` and `fd_fma` and compares exit code and commit log with the native run. |
| D11. CI and build hygiene | `cargo build`/`test --all-features` need no C++ toolchain or SystemC. The C ABI gets a plain-C compile-and-link smoke in the `Quality and tests` job. The SystemC smoke runs in a new CI job on the dev image. The unused `RiscvCore::tlm_interface` field and the `src/tlm` components stay unchanged; a test proves the field routes no access. |
| D12. Documentation | `docs/integration/systemc-tlm.md` becomes the normative reference for the selected blocking-transport mapping, FFI ownership and threads, error mapping, time unit, re-entrancy and stop behavior, and build and version pins; DMI lifetime and quantum/synchronization stay open there. The README, CLI help, CHANGELOG and verification docs state the transport option, the `MachineConfig` change, the C ABI and the SystemC pin. |

## 3. Ownership and semantics

The Machine owns the transport selection as composition configuration; the Platform owns the RAM route, its installation and its reset, as amended in ADR-0003. The TLM route is another implementation behind the existing validated physical and atomic access boundary, per ADR-0002 §8, not a second Hart path. In the SystemC host the external kernel owns global time and the outer thread; the C ABI host is a Runner-side adapter that only grants budgets and classifies results, per ADR-0003 and ADR-0004 §4.4.

## 4. Sequenced units and acceptance

These are requirements for subsequent implementation. Activating this contract does not implement them.

| Unit | Required observable proof |
| --- | --- |
| U1. Rust TLM RAM route | Per D2–D4, D6 and D11: the adapter vocabulary, the selectable RAM slot with every RAM user routed through it, `MachineConfig.transport` and `run --transport`, request and status mapping, debug-transport installation and host views, unknown-completion poisoning and reset, RAM zero-fill on reset. Rust parity tests for widths, bytes, every status and injected host/protocol/unknown completions, one transaction per access, debug SBA and program-buffer RAM access through the route, rejection of `Flat` with `tlm`, a zero RAM window after reset with a previously dirtied shared target, debug-transport failure classification, and a test that `tlm_interface` routes no access. |
| U2. Atomic extension | Per D5: every AMO, LR and SC outcome over the extension matches native; a target without the extension yields the access fault; a counting target proves exactly one transaction per atomic and no read-then-write. |
| U3. Delay and time | Per D7: exact and rounded-up conversion, a response above the declared maximum delay reported as a simulator failure with its overshoot, debug-initiated delay not charged to `mtime`, overflow and malformed-delay failures, consumption by outcome per ADR-0004 §5.3, `mtime` advanced by turns plus delay ticks, counters unaffected, and the boundary-fact total. |
| U4. Guest parity | Per D10: the guest suite's second pass under `--transport tlm` and byte-identical commit logs for the parity set. Native results and A10 unchanged. |
| U5. C ABI | Per D8 and D11: a build of `--all-features` with no C++ toolchain, the grant/return time fields with the earlier-start rejection, profile selection and commit-log output, header, `capi` module and plain-C smoke in CI covering lifecycle, wrong-thread and re-entry rejection, panic poisoning, and an unknown completion followed by reset. |
| U6. SystemC smoke | Per D9: the reviewed dev-image change with the pinned SystemC build, `integration/systemc/` and the new CI job running both smoke guests with native comparison. |
| U7. Exit | Per D12, the documentation is complete and accurate. CI runs the full Rust quality gate, the guest suite with its TLM pass, the C ABI smoke, the SystemC smoke, the tool script and the mutation runner. Obtain an independent review of the final committed PR head. The A10 oracle and certification deferral remain unchanged. |

Dependencies: U1 first. U2 and U3 require U1 and may proceed in parallel. U5 requires U3. U4 requires U2 and U3. U6 requires U2 and U5. U7 requires all.

Required negative controls, under the existing mutation-runner pattern:

- the default transport not being native;
- `TLM_GENERIC_ERROR_RESPONSE` mapped to a guest-visible fault;
- an incomplete or target-modified payload accepted as completion;
- one access split into, or merged with, another transaction;
- `tohost` polling or image installation issued through `b_transport`;
- an AMO emulated as a separate read and write;
- a positive sub-tick delay rounded down to zero;
- transport delay counted into `mcycle` or `minstret`;
- an access issued after an unknown completion without reset;
- a callback re-entering the C ABI accepted;
- a TLM status, or a host stop before a terminal result (the C-ABI stand-in for `sc_stop`, expressed as a Rust test), reported as a passing ruscv-sim result; the SystemC job also runs an early-`sc_stop` variant that must not pass.

Keep their small patches, commands and expected assertions under the existing mutation-runner pattern. The standard gate and the no-ledger rule are unchanged.

## 5. Exclusions and retained direction

No DMI, `nb_transport`, TLM phases beyond blocking, TLM-modeled CLINT/PLIC/UART/HTIF, SystemC-modeled interrupt lines, temporal decoupling or quantum keeper, multi-Hart or DMA, inbound masters other than the existing DM, non-Linux FFI targets, package or crate publication, A10 change, ACT4 selection change, or new ISA extension or profile.

DMI for a qualified RAM region, with permissions, latency, invalidation and breakpoint/self-modifying/MMU/atomic interactions, is the retained next step of Stage 7 and requires its own contract. Non-blocking transport requires a separately approved timing contract. Stage 8 remains conditional.

## 6. Activation boundary

This documentation-only rotation preserves the entire RV64GC default-profile contract, applies the bounded 2026-11-04 blocking-transport amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle.
