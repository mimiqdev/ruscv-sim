**Status:** Historical. Completed 2026-11-08 at PR #236; the [Host HTIF Service contract](../../dev-plan.md) succeeds it as the sole Current contract on the actual rotation merge.

**Authority:** Preserved approved contract, not an active plan or an execution report. CI and PR history retain check and review outcomes.

**Original approval:** 2026-11-07. After the non-blocking contract completed, the maintaining agent selected TLM-modeled devices, the retained direction of the non-blocking contract §5 and of roadmap Stage 7, under the owner's delegation of full planning authority; decisions D1–D10 were selected. Activated by PR #226 (`147b923`). The [proposal entry](../../proposals/post-nb-tlm-devices.md) is informational.

**Completion:** Units U1, U2, U3, U4 and U5 merged as PR #232 (`ce80cd8`), #233 (`7457db5`), #234 (`305ccda`), #235 (`3936736`) and #236 (`47f9d34`), for issues #227, #228, #229, #230 and #231, completed 2026-11-08 at merge head `47f9d34`. The contract-rotation merge that activates the successor formally archives this contract; execution and review outcomes stay in CI and PR history.

**Known limitations:** The host may supply only the UART window; the HTIF window is an in-tree target, so host HTIF service remains retained direction. No device target may annotate delay or let host time pass inside its callback, no device window offers direct memory, no atomic envelope reaches a target, no non-blocking device transport or device phase exists, and one device transaction is outstanding at a time. CLINT, PLIC and the source-1 gateway are not device targets, and no SystemC-modeled interrupt line exists. A host-served UART window has no Rust register state: `uart_inspection` returns `None` and a typed `MemoryInterface` access to it is `MemoryError::InvalidAddress`. The ABI adds no entry that pushes a byte into a window, so `receive` is reached only by an embedding caller's own UART receive path. The smoke's host UART is a model of the register set its guest uses, and the contract makes no claim about a host target that models different register values. The SystemC smoke requires Linux x86-64 at the pinned SystemC 3.0.2 commit `70b0fc8e4a74acc677b0fc73cea08f940c2115d5`. `--all-features` never builds the SystemC host, so the three device fault options are covered by that smoke and are not mutation-runner cases. The C ABI is append-only, and `ruscv_payload` grew from 272 to 280 bytes, so a host must recompile against the new header; the public `MachineConfig.devices` field breaks struct-literal construction by external code. Issue #207, a possible underflow of a grant's consumed time when a guest lowers `mtime` inside a grant, stays open outside this contract. The A10 oracle and the Stage 3 performance-certification waiver are unchanged, and this contract makes no wall-clock claim.

## 1. Objective and inherited profile

Make a platform device a blocking TLM target on the TLM route: one device register access becomes one `b_transport` transaction carrying the existing physical category and initiator, answered either by the in-tree Rust device or by a target the SystemC host supplies through the C ABI, with the same status mapping, the same guest-visible side effects and the same Platform events as today. A host-served device owns one window's register state and nothing else: Platform time, the interrupt lines, routing and run control stay where they are. With no host target, a run is exactly today's run on either route.

Today only the guest-RAM slot is a transport target. `--transport tlm` builds `Transport::tlm(Arc::new(ZeroDelayRam::new()))` (`src/main.rs:250`) and `MachineConfig.transport` carries that one target (`src/machine/mod.rs:154`); `RamSlot` is either the native `SimpleMemory` or that blocking target (`src/ram.rs:48`). Device registers never reach it: `SystemBus::native_transact_from` matches RAM first by `contains_range` and then runs the CLINT, PLIC, gateway, UART and HTIF branches (`src/executor.rs:858-1060`), and each of those branches is Rust state on the bus, on the native and the TLM route alike. The UART window is `0x1000_0000` with `0x100` bytes (`src/executor.rs:185-188`) over a `Uart16550` whose own `UART_SIZE` is 8 (`src/peripherals/uart16550.rs:38`); a raw access is byte-only, rejects fetches and rejects every atomic width (`src/executor.rs:929-981`, `:1122-1134`). HTIF is an exact eight-byte endpoint at `0x4000_8000` (`src/executor.rs:189-192`) whose dword write fires `htif_write_callback` with the written value and whose dword read returns zero (`src/executor.rs:983-1046`, `:1204-1214`). The UART publishes a transmitted byte from `write_thr`, before the FIFO check (`src/peripherals/uart16550.rs:399-410`), through the callback `Platform::build` installs to push `PlatformEvent::UartTransmit` and call `config.uart_output` (`src/machine/platform.rs:172-190`). CLINT and PLIC are read by the Platform itself for `mtime`, `mtimecmp` and the four lines (`src/executor.rs:362-381`), and the PLIC source-1 level, its pending reconciliation and claim/complete are bus state (`src/executor.rs:627-643`, `:726-828`). Each `Installed::build` constructs a fresh `Platform` (`src/machine/mod.rs:522`), so device state is reset by construction today, while the RAM slot's `begin_window` asks its target for a transport reset and zero-fills the window (`src/ram.rs:215`). The blocking adapter queries direct memory once, after an `Ok` Hart-initiated non-atomic transaction that set `dmi_allowed` (`src/blocking/adapter.rs:734-752`), and only RAM can reach it. `src/tlm`'s `TlmBus` and the peripherals' `TlmTarget` implementations are component code with component tests (`tests/tlm_tests.rs`, `tests/peripheral_tests.rs`); they are not this route, and `src/blocking` is deliberately separate from `src/tlm` (`src/blocking/mod.rs:3`).

The inherited profile is everything delivered through the completed non-blocking contract: the selectable native or TLM RAM route, `ZeroDelayRam`, the atomic extension, declared-maximum delay accounting, direct memory, the quantum, the non-blocking AT path with its retirement rules, the append-only C ABI and the pinned SystemC 3.0.2 smoke, over the default RV64GC profile with M/S/U, Debug Specification 1.0 and zero-entry PMP plus Sv39.

The inherited Stage 3 performance-certification waiver continues. `tools/a10/public-v1.json`, its fixtures and its pinned argv stay unchanged, and A10 runs only on the native route. This contract makes no wall-clock claim.

Vocabulary used throughout:

- A *device window* is one fixed platform register range: the UART window `0x1000_0000`/`0x100`, or the HTIF endpoint `0x4000_8000`/8.
- A *device target* is a `BlockingDeviceTarget`: the object that owns one window's register state and answers its transactions.
- The *in-tree target* is the Rust device that answers a window today; the *host target* is one the C ABI supplies.
- A *device transaction* is one validated physical request routed to a device window, carried as one `BlockingTransaction` with `BlockingInitiator` provenance.
- A *device event* is the at-most-one guest-visible effect a device transaction reports beyond its register result: a UART transmit byte or an HTIF write value.
- A *host view* is a Platform read or write of device state outside any transaction: `Platform::uart_inspection`, `Platform::receive_uart`, or a typed `MemoryInterface` read of the window.
- A *parity run* is the same guest with the same options and no host device target: the native route when the comparison is architectural, or the in-tree pass of the same quantum selection when it is about quantum facts.

Selection and shape | `MachineConfig` gains a public `devices: DeviceTargets` field; `MachineConfig::new` selects `DeviceTargets::none()`. `src/blocking/device.rs` adds `BlockingDeviceTarget`, `BlockingDeviceEvent` and `DeviceTargets`. `BlockingDeviceTarget` has three methods, all `&self`: `b_transport(&self, &mut BlockingTransaction<'_>)`, `receive(&self, byte: u8)`, and `transport_reset(&self) -> bool`. Windows and in-tree targets | Two windows are device targets. **UART**: the in-tree target wraps the existing `Uart16550`; the Platform keeps today's window policy before the target, so byte-only width, fetch rejection, the `0x100` window and the eight-byte device range keep their current answers and diagnostics (`src/executor.rs:929-981`), and the native branch and the in-tree target share one register helper so the two routes cannot answer differently. **HTIF**: the in-tree target serves the dword read as zero and the dword write as an accepted write with one `HtifWrite` event; the exact-start, dword-width and fetch rules stay in the Platform, and the atomic RMW envelope stays in the Platform, is still never a device transaction, and keeps its old value of zero (`src/executor.rs:983-1046`, `:1136-1189`). **Not targets**: CLINT (`mtime`/`mtimecmp`/`msip`), PLIC (priority, pending, enable, threshold, claim/complete, contexts) and the source-1 gateway word at `0x4000_0000`. They stay `SystemBus` state on both routes with today's width, alignment and flush rules, because they own Platform time, the presented lines and the gateway's retraction rule; a device target cannot own them without moving time or line authority out of the Platform (ADR-0003, ADR-0004). Host replacement is offered for the UART window only; the HTIF window is an in-tree target in this contract, and host HTIF service is retained direction. |
| D4. Ordering, accounting and events | A Hart-origin device access still flushes the local offset under the bus lock before the target sees it (quantum F1, `src/executor.rs:905-915`), so a device transaction observes committed Platform time and can neither read nor move the offset; a `DebugInbound` access runs at a debug boundary, where the offset is already zero. The register side effects happen once, inside the one access, in request order. A device transaction adds nothing to `transport_delay_femtoseconds`, `host_elapsed_femtoseconds`, `mcycle`, `minstret`, the turn completion bound or a grant's horizon: annotation is fixed at zero and a non-zero value is a protocol failure (D2). It therefore adds no committed or local time, and the quantum and grant arithmetic keep their parity values; the F1 flush that precedes a Hart device access is today's rule, is unchanged, and commits only offset a turn had already accrued. Each window has one publication sink on the `SystemBus`, installed once by `Platform::build`: the UART sink pushes `PlatformEvent::UartTransmit(byte)` and then calls `config.uart_output(byte)`, and the HTIF sink pushes `PlatformEvent::HtifWrite(value)` and then calls `config.htif_write(value)`, which is exactly what today's `set_htif_write_callback` closure does (`src/machine/platform.rs:193-203`). Both public `MachineConfig` callbacks are therefore still called, in the same order and with the same values. A response's device event is published through its window's sink only for an `Ok` status; an event attached to any other status is a protocol failure, and an unknown completion keeps the precedence the archived non-blocking contract's D4 step 1 gave it, so nothing is published. Every publishing path calls the window's sink: the raw Hart write on both routes, a host target's response, the typed byte write of the UART window (`src/executor.rs:1319-1332`), the HTIF RMW envelope (`src/executor.rs:1181-1186`) and the typed HTIF dword write (`src/executor.rs:1288-1294`). An event that does not match its window is a protocol failure. |
| D5. Debug, SBA and host views | A `DebugInbound` request to a device window is the same device transaction with `BlockingInitiator::DebugInbound`, so a debugger and SBA see the same device state as the Hart; its delay and host elapsed must be zero and are not charged, a target fault maps to the existing normalized fault and `sberror` taxonomy, and a protocol or host failure keeps its current non-guest classification. The atomic path is unchanged and never reaches a target (D3). A host view of the in-tree UART keeps today's meaning: `uart_inspection` reads its state and `receive_uart` injects a byte. A host-served UART window has no Rust state to view, so `uart_inspection` returns `None`, `receive_uart` calls the target's `receive`, and a typed `MemoryInterface` access to that window returns `MemoryError::InvalidAddress` for a read and for a write, instead of reading or mutating a stale object; the typed byte write of an in-tree window keeps today's behavior, applies the register write and publishes through the UART sink (D4). Direct memory is never offered for a device window, and the protection is dispatch rather than a range check: `SystemBus` hands the RAM slot only a request whose whole span it has already matched as RAM (`src/executor.rs:876-903`), a device span takes the device path instead, a device target has no `get_direct_mem_ptr`, and the device path never sets `dmi_allowed` and never queries. `TlmRamAdapter` itself validates a grant's shape, address, permission and latency (`src/blocking/adapter.rs:857`) but does not clamp it to the image window, so the rule this contract states is that no request routed to a device can reach a direct-memory query or copy. |
| D6. Reset and lifecycle | A fresh `Platform` is built for every install (`src/machine/mod.rs:522`), which is the whole reset rule for an in-tree target. For a host target, `Platform::build` calls the selected target's `transport_reset` once, beside `RamSlot::begin_window` (`src/ram.rs:215`) and before the image is placed, and every reinstall takes the same path, including `fresh_reset`, `reload_for_ndmreset` and `ruscv_machine_reset`. No device transaction outlives a Platform: `b_transport` returns inside the instruction that issued it, so a reset cannot run under a live device callback. The event queue is per Platform, so a generation inherits no device event. |
| D7. Parity and determinism | With no host target, the in-tree targets are today's device code through one indirection, so every guest's TLM pass keeps its native route run's exit code, byte-identical commit log, `config.uart_output` byte sequence, `config.htif_write` value sequence and zero `BoundaryFacts` transport totals at the same options, and its `mtime` and `PlatformEvent` sequences are the ones that run shows today. `BoundaryFacts.quantum` is compared only with the parity run of the same quantum selection and never with a native run, which has no quantum facts: a selected quantum reports its own ticks, syncs and reduced-accuracy flag, exactly as it does today, and a quantum pass is compared with the native route only for the architectural facts above. `hello` (`tests/bare-metal-riscv-test/rv64i/hello.S`) is in `PARITY_GUESTS` (`scripts/run_elf_tests.sh:74`) and the suite requires `Hello!` on every pass (`:116`), so the UART route's parity is already a suite condition. A host UART adds no time, thread, wall clock or scheduling dependence: one access is one transaction, the sequence is the Hart's instruction sequence, and two runs of a guest with the same host target produce the same bytes, commit log and exit code. This contract makes no claim about a host target that models different register values from the in-tree device; the smoke's guest fixes the values that must agree. |

## 3. Device ownership, ordering and events

The Platform keeps the window map, the pre-target policy, routing, the event queue and the presented lines; a device target owns one window's register state. The Machine owns admission, lifecycle and reset. The Hart is unchanged and never sees a target, a transaction or an event. The C ABI carries one table per window and the in-tree targets are the reference behavior a host target must reproduce for the guests the smoke runs.

| Window | Base and size | Today | This contract |
| --- | --- | --- | --- |
| UART | `0x1000_0000`, `0x100` | `SystemBus` `Uart16550`, byte-only raw access, callback publication (D1) | In-tree device target by default, host target through the C ABI; the same pre-target policy and one event publication site |
| HTIF | `0x4000_8000`, 8 | `SystemBus` endpoint: dword read zero, dword write fires the callback, atomic RMW envelope (D1) | In-tree device target for the plain dword read and write; the atomic envelope stays in the Platform |
| CLINT | `0x0200_0000`, `0xC000` | `SystemBus` `Clint`; `mtime`, `mtimecmp`, `msip`, MTIP/MSIP | Unchanged on both routes; not a device target |
| PLIC | `0x0C00_0000`, `0x40_0000` | `SystemBus` `Plic`; priority, pending, enable, threshold, claim/complete, MEIP/SEIP | Unchanged on both routes; not a device target |
| Source-1 gateway | `0x4000_0000`, 4 | `SystemBus` level word and its pending reconciliation | Unchanged on both routes; not a device target |

Zero delay means any annotation is a protocol failure. ## 4. Sequenced units and acceptance

These are requirements for subsequent implementation. Activating this contract does not implement them.

| U1. Device path and in-tree targets | Per D1–D4 and D7: `BlockingDeviceTarget`, `BlockingDeviceEvent`, `DeviceTargets`, the device adapter, the UART and HTIF windows routed through the selected target on the TLM route, the two publication sinks, the in-tree targets, `Uart16550::write_reg_reporting` and the RAM adapter's rejection of a device event. - `--fault-uart-no-lsr`: `UartTarget` answers `LSR` with the transmit-empty bit clear. `hello` must exhaust its cycle bound and fail rather than pass.
- `--fault-uart-wait`: `UartTarget::b_transport` waits one tick. The run must report a failure whose diagnostic names host elapsed time on a device transaction.

## 5. Exclusions and retained direction

No SystemC-modeled interrupt line or interrupt controller, no device target for CLINT, PLIC or the source-1 gateway, no host HTIF service, no device delay annotation, no device host-time suspension, no device direct memory, no device atomic envelope, no non-blocking device transport or device phases, no more than one outstanding device transaction, no DMA, multi-Hart, arbitration or coherence, no second RAM target, no inbound master other than the existing DM, no `tlm::` `TlmBus` routing on the public path, no change to the native route's device answers, no checkpoint or restore, package or crate publication, A10 change, ACT4 selection change, wall-clock performance claim, or new ISA extension or profile. Issue #207 stays open outside this contract.

Retained direction, each needing its own approved contract: host HTIF service through the same window-indexed table; device delay and host-time annotation with the turn bound and grant horizon extended to match; CLINT or PLIC targets only if time and line authority move under an accepted ADR amendment; SystemC-modeled interrupt lines; and a UART inspection snapshot for a host-served window.

## 6. Activation boundary

This documentation-only rotation archives the non-blocking contract, applies the bounded 2026-11-07 device-target amendments to ADR-0002, ADR-0003 and ADR-0004, and activates this target atomically on merge. It does not assert runtime support, start implementation, change the dev image, publish a release or seal an oracle. Later implementation must meet the units above on its own reviewed commits.
